aspect oriented programming 의 약자로 관점 지향 프로그램이다.
관점에 따라서 핵심 기능과 부가 기능을 분리하고 분리한 부가기능의 적용처를 선택하는 방식.

객체지향 프로그래밍 [[OOP]]의 한계를 보완하기 위해서 나타났다.
객체지향 프로그래밍 [[OOP]]의 한계란?
결국 객체별로 나눠서 프로그래밍 하나,... 로깅이나 오류 처리 트랜잭션, 보안 처리 등등 공통의 **관심사** 가 존재하기 마련이고, 이것들은 결국 코드에서 중복되어 나타난다.
결국 로깅 방식이 바뀌거나 보안 정책이 바뀌면 일일히 다 수정해야하는 번거로움을 처리하기 위해..
이러한 공통 관심사를 분리하는게 **횡단 관심사 분리** [[AOP]]의 시작이다.


[[AOP]] 사용할 때의 주의점 :
같은 Transactional 에서 내부 클래스 호출이나, final, private에서 작동하지 않는다.
그 이유는 final과 private은 오버라이딩이 안되기 때문에 proxy가 씌워지지 않는다. @Aspect 어노테이션이 적용이 안됨..
