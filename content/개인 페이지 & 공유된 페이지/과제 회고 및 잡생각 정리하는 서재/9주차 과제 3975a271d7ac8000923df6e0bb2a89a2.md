게시글에 이미지를 올리며 테스트 도중 1mb 이상의 파일을 올리니 500 서버 오류가 떴다.

찾아보니, spring에서는 기본적으로 1mb 이미지까지 허용해서 일어나는 일이라고 한다.

파일 크기 오류는 처리되지 않은 exception이라 당황해서 원인을 코드 단계에서 찾다 보니 흔히 말해 삽질을 한거 같다

결론적으로는 오류 처리의 중요성을 깨달았다..

comments에서 원하는 값만 골라서 읽을 수 있는 injection도 찾아보며 알게 되었다. 간단한 interface injection만 찾아보고 적용 하였다.

home에서 최신 5개의 post를 가져와 필요한 데이터를 뽑아 활용하는데,

처음에는 postPreviewResponse dto를 따로 만들어서 필요한 데이터만 가져와야지 하고 단순하게 생각했는데,

repository에서 N+1 문제에 신경쓰며 fetch join을 알아보던 중 ai에게 fetch join 쿼리를 물어보았고,

AI가 컬렉션 fetch join(뻥튀기 문제) 에 대해 설명해줘서 batch size와 entity graph로 해결하는게 낫다고 답변 받았다.

Fetch Join: 쿼리 1번이지만 행 중복과 페이징 문제가 있음
Entity Graph + Batch size : 쿼리 2번이지만 페이징이 정확하고 데이터 중복이 적음

여기서 드는 의문점이 그러면 상세 페이지에서 comment도 컬렉션인데 왜 fetch join으로 했을까?에 대해서 생각했다.

정답은 comment에는 username이 있어서 매번 comment를 가져오고 comment.getUsername()을 해줘야 한다는 것. 즉 복잡한 연관 관계에서는 fetch join이 해결책이 될 수도 있다는 것을 알게 됐다.
