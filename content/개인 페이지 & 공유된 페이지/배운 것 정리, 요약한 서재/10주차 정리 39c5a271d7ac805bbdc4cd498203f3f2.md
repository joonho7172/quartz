# 10주차 정리

Custom Hook

useState나 useEffect.. useMemo, useCallback 같은 메소드를 조합해서 상태 관리 로직을 하나의 함수로 묶는 방법이다. 반드시 use로 시작해야하고 컴포넌트나 다른 hook의 최상위에서 호출 해야만 함.

예시로 useFetch등(useEffect와 use state를 같이 사용하는 경우로) ,, 그리고 얘네들은 상태를 공유하는 것이 아님. 반복해서 쓰이면 그만큼 새로운 상태 객체가 생성됨. 쓰는 이유는 유지보수성, 가독성, UI와 로직 분리 등..

context

props drilling을 줄이기 위해서 트리 위쪽의 값을 직접 꺼내 쓰는 값 전달 도구.. 로그인 사용자나 테마, 언어 설정 같은 전역 세팅이 여기에 들어가기 적합함. (서로 멀리 떨어진 컴포넌트에서 필요로 하는 대표적인 값들)

provider라는 컴포넌트에 value라는 값을 전달하고 useContext를 통해서 값을 읽는다.

서버에서 읽어오는 값들은 context가 아닌 react query나 swr 같은 상태 관리 도구가 더 적합함.

suspend

아직 준비되지 않은 UI 영역을 대기 시켜 fallback을 보여주는 경계

준비되지 않은 모든 비동기 작업을 기다려주지는 않는다. 예시로 useEffect의 fetch 같은것.

promise나 suspense를 지원하는 프레임워크나 react 데이터 패칭 도구가 있어야 작동함.

error boundary

컴포넌트 렌더링 중 발생한 오류가 앱 전체로 퍼지는 것을 방지하는 경계. 

fallBack으로 오류가 난 컴포넌트의 UI를 대체해서 UX를 좋게 만들고, 오류를 별도 컴포넌트로 분리하고 싶으면 fallBackComponent를 쓰기도 함.

concurrent rendering

렌더링 작업을 잘게 나누고 우선순위를 조정 할 수 있게 해주는 렌더링 방식.

사용방법은 useTransition 메소드로 개발자가 react에게 우선순위를 알려주는 방식

속도가 빨라지거나 병렬처리로 성능 향상이 되는건 아님. 그냥 부드럽게 보이기 위함

사용 예를 들어 입력값은 즉시 반영되어야 하므로 일반 state로 처리, 그로 인해 발생하는 무거운 필터링이나 렌더링을 transition으로 처리.

route

SPA는 처음에 HTML이랑 JS 불러오고 새로고침하지 않고 화면만 바꾸는데 주소가 그대로면 혼란이 생길 수 있음.

URl에 화면 상태를 담기 위해서 사용함.

path parameter나 query parameter 생각하면 될듯.
