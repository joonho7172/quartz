# 26일차 배운 것(JS, 네임 스페이스, 패러다임)

## 1. JavaScript 실행 흐름

JavaScript 코드는 단순히 위에서 아래로 실행되는 것처럼 보이지만, 실제로는 **JavaScript 엔진**과 **런타임 환경**이 함께 처리한다.

JavaScript 엔진은 코드를 해석하고 실행한다.

브라우저나 Node.js 같은 런타임은 `setTimeout`, DOM, fetch 같은 기능을 제공한다.

즉, JavaScript를 이해하려면 다음 두 가지를 구분해야 한다.

```
JavaScript 엔진: 코드를 실행하는 핵심 장치
JavaScript 런타임: 엔진 주변에서 비동기, DOM, 타이머 등을 제공하는 환경
```

# 2. 객체

JavaScript에서 객체는 **key-value 쌍으로 이루어진 프로퍼티의 집합**이다.

쉽게 말하면, 객체는 **이름표가 붙은 값들을 모아둔 사물함**이다.

```
name이라는 칸에 "John"
age라는 칸에 30
```

이런 식으로 관련 있는 값들을 하나로 묶는다.

---

## JavaScript의 타입

JavaScript의 값은 크게 두 종류로 나눌 수 있다.

```
1. 원시 타입
2. 객체 타입
```

원시 타입은 다음과 같다.

```
number, string, boolean, undefined, null, symbol, bigint
```

이 원시 타입을 제외한 대부분은 객체다.

배열도 객체고, 함수도 객체다.

주의할 점은 `typeof null`의 결과가 `"object"`로 나오지만, 실제로 `null`은 원시 타입이다.

---

## 객체는 참조로 다뤄진다

객체는 값 자체가 변수에 들어가는 것이 아니라, **객체가 있는 위치를 가리키는 참조값**이 들어간다.

그래서 객체 비교는 내용 비교가 아니라 **같은 객체를 가리키는지**를 비교한다.

```
{}=== {}// false
```

둘 다 빈 객체지만 서로 다른 객체이기 때문에 false다.

반대로 같은 객체를 공유하면 true가 된다.

```
consta= {};
constb=a;

a===b// true
```

---

# 3. 객체를 사용하는 이유

객체를 사용하는 이유는 **관련 있는 데이터와 기능을 하나의 단위로 묶기 위해서**다.

예를 들어 사람의 이름, 나이, 인사 기능을 따로 관리하는 것보다 `person`이라는 객체 안에 묶으면 관리하기 쉽다.

React에서 컴포넌트로 넘기는 `props`도 결국 객체다.

```
props = 컴포넌트에 전달되는 값들을 모아둔 객체
```

---

# 4. 객체를 만드는 방법

객체를 만드는 대표적인 방법은 3가지다.

```
1. 객체 리터럴
2. 생성자 함수
3. class 문법
```

## 객체 리터럴

`{}`를 사용해서 객체를 직접 만드는 방식이다.

가장 기본적이고 자주 쓰인다.

## 생성자 함수

`new`와 함께 사용해서 비슷한 구조의 객체를 여러 개 만들 때 사용한다.

다만 생성자 함수 안에 메서드를 직접 넣으면 객체를 만들 때마다 같은 함수가 계속 복제될 수 있다.

이 문제를 해결하는 개념이 **프로토타입**이다.

---

# 5. 프로토타입

프로토타입은 객체들이 공통으로 사용할 기능을 공유하기 위한 구조다.

생성자 함수 안에 메서드를 직접 넣으면 인스턴스마다 함수가 복제된다.

하지만 메서드를 프로토타입에 넣으면 여러 객체가 하나의 메서드를 공유할 수 있다.

```
user1 ─┐
user2 ─┼──> User.prototype.sayHello
user3 ─┘
```

즉, 프로토타입은 **메서드 중복 생성을 막고 공유하기 위한 구조**라고 이해하면 된다.

---

# 6. class 문법

JavaScript의 `class`는 내부적으로 프로토타입을 기반으로 동작한다.

겉보기에는 Java의 class처럼 보이지만, JavaScript의 class는 프로토타입 기반 문법을 더 보기 좋게 만든 것이다.

그래서 흔히 **문법적 설탕**이라고 부른다.

다만 생성자 함수와 100% 같은 것은 아니다.

차이점은 다음과 같다.

```
1. class는 반드시 new로 호출해야 한다.
2. class 내부는 자동으로 strict mode다.
3. class 메서드는 프로토타입에 저장된다.
4. extends, super 같은 상속 문법을 제공한다.
```

클래스 안에서 `#name`처럼 `#`을 붙이면 private 필드를 만들 수 있다.

```
#name = 클래스 외부에서 직접 접근할 수 없는 private 필드
```

---

# 7. 네임스페이스

네임스페이스는 **이름 충돌을 막기 위해 관련된 식별자들을 하나의 그룹으로 묶는 방법**이다.

JavaScript에는 Java의 `package`나 C#의 `namespace` 같은 전용 문법이 없다.

그래서 예전에는 객체를 하나 만들고 그 안에 관련 변수와 함수를 넣어서 네임스페이스처럼 사용했다.

```
전역 스코프
└── MyApp
    ├── init
    ├── login
    └── logout
```

이렇게 하면 전역에는 `MyApp` 하나만 올라가므로 이름 충돌을 줄일 수 있다.

네임스페이스가 필요한 이유는 **전역 스코프 오염** 때문이다.

여러 파일에서 `init`, `count`, `login` 같은 이름을 전역에 만들면 서로 충돌할 수 있다.

현대 JavaScript에서는 객체 네임스페이스보다 **ES Module**을 더 많이 사용한다.

---

# 8. 프로그래밍 패러다임

프로그래밍 패러다임은 **코드를 어떤 방식으로 구조화할 것인가에 대한 사고방식**이다.

대표적으로 다음이 있다.

```
절차 지향
객체 지향
함수형
```

JavaScript는 하나의 패러다임에만 묶이지 않는 **멀티 패러다임 언어**다.

즉, 상황에 따라 절차 지향처럼도, 객체 지향처럼도, 함수형처럼도 작성할 수 있다.

---

# 9. 함수

함수는 **재사용하기 위해 묶어놓은 코드의 집합**이다.

함수는 입구와 출구가 있는 상자로 볼 수 있다.

```
입구: 매개변수
처리: 함수 내부 로직
출구: 반환값
```

JavaScript에서 함수를 만드는 방법은 대표적으로 3가지다.

```
1. 함수 선언문
2. 함수 표현식
3. 화살표 함수
```

## 함수 선언문

선언 전에 호출할 수 있다.

이유는 함수 선언문이 호이스팅되기 때문이다.

## 함수 표현식

함수를 변수에 담는 방식이다.

변수에 할당된 이후부터 사용할 수 있다.

## 화살표 함수

짧게 함수를 작성할 수 있는 문법이다.

자기만의 `this`를 가지지 않고, 바깥의 `this`를 따른다.

---

# 10. 호이스팅

호이스팅은 선언이 코드의 위로 끌어올려진 것처럼 동작하는 현상이다.

정리하면 다음과 같다.

```
함수 선언문: 선언 전에 호출 가능
함수 표현식: 할당 이후 호출 가능
화살표 함수: 할당 이후 호출 가능
```

함수 표현식과 화살표 함수는 보통 `const`나 `let`에 담기 때문에, 선언 전에 접근하면 에러가 난다.

---

# 11. 객체 반환과 배열 반환

함수는 객체나 배열도 반환할 수 있다.

객체 반환은 **이름으로 꺼내 쓰는 것이 자연스러울 때** 사용한다.

```
name, age, email처럼 각각의 의미가 중요하면 객체
```

배열 반환은 **순서로 꺼내 쓰는 것이 자연스러울 때** 사용한다.

```
x, y 좌표
React의 useState처럼 첫 번째, 두 번째 순서가 정해진 경우
```

React의 `useState`는 배열을 반환한다.

```
const [count,setCount]=useState(0);
```

첫 번째는 상태값, 두 번째는 상태를 바꾸는 함수다.

---

# 12. 구조 분해 할당

구조 분해 할당은 객체나 배열 안의 값을 꺼내서 변수에 담는 문법이다.

객체는 이름으로 꺼낸다.

```
const { name, age } = user;
```

배열은 순서로 꺼낸다.

```
const [count, setCount] = useState(0);
```

인자가 많을 때는 객체로 묶어서 넘기고, 함수 안에서 구조 분해 할당으로 받으면 코드가 깔끔해진다.

---

# 13. 함수형 패러다임

함수형 패러다임은 함수를 중심으로 코드를 구성하는 사고방식이다.

핵심 개념은 다음과 같다.

```
1. 순수 함수
2. 불변성
3. 일급 함수
4. 고차 함수
```

React는 함수형 사고와 연결이 깊다.

함수형 컴포넌트는 `props`를 받아서 UI를 반환하는 함수처럼 볼 수 있다.

```
props 입력
   ↓
컴포넌트 함수
   ↓
UI 반환
```

---

# 14. 순수 함수

순수 함수는 두 가지 조건을 만족하는 함수다.

```
1. 같은 입력이면 항상 같은 출력
2. 외부에 부수 효과를 일으키지 않음
```

예를 들어 더하기 함수는 순수 함수다.

```
add(1, 2)는 언제 실행해도 3
```

하지만 외부 변수를 읽거나 바꾸면 순수 함수가 깨질 수 있다.

특히 외부 상태를 바꾸는 것은 부수 효과다.

---

# 15. 부수 효과

부수 효과는 함수가 반환값 외에 외부 세계에 영향을 주는 것이다.

예를 들면 다음이 있다.

```
외부 변수 변경
객체나 배열 직접 수정
console.log 출력
DOM 변경
네트워크 요청
DB 저장
```

순수 함수는 이런 부수 효과를 만들지 않는다.

순수 함수를 쓰면 다음 장점이 있다.

```
테스트가 쉬움
디버깅이 쉬움
재사용성이 좋아짐
메모이제이션이 쉬움
```

---

# 16. React와 순수 함수

React 컴포넌트는 가능하면 순수 함수처럼 작성해야 한다.

즉, 같은 `props`와 같은 `state`라면 같은 UI가 나와야 한다.

렌더링 중에 외부 변수를 바꾸거나 네트워크 요청을 보내면 안 된다.

네트워크 요청, 타이머, DOM 조작 같은 부수 효과는 `useEffect`에서 처리한다.

```
렌더링: 순수하게 UI 계산
useEffect: 부수 효과 처리
```

---

# 17. 불변성

불변성은 기존 값을 직접 바꾸지 않고, 새로운 값을 만들어 사용하는 것이다.

React에서 상태를 바꿀 때는 기존 객체나 배열을 직접 수정하면 안 된다.

```
나쁜 방식: 기존 배열에 push
좋은 방식: 새 배열을 만들어 setState
```

React는 참조 비교를 많이 사용하기 때문에, 새 객체나 새 배열을 만들어야 변경을 감지하기 쉽다.

---

# 18. 일급 함수

일급 함수란 **함수를 값처럼 다룰 수 있다는 언어의 성질**이다.

JavaScript에서 함수는 값처럼 다뤄진다.

그래서 다음이 가능하다.

```
1. 함수를 변수에 저장할 수 있다.
2. 함수를 객체나 배열에 저장할 수 있다.
3. 함수를 다른 함수의 인자로 넘길 수 있다.
4. 함수를 다른 함수의 반환값으로 사용할 수 있다.
```

즉, 함수가 숫자나 문자열처럼 값으로 취급된다.

---

# 19. 고차 함수

고차 함수는 다음 중 하나를 만족하는 함수다.

```
1. 함수를 인자로 받는 함수
2. 함수를 반환하는 함수
```

`map`, `filter`, `reduce`는 대표적인 고차 함수다.

```
map: 배열의 값을 변환
filter: 조건에 맞는 값만 남김
reduce: 배열을 하나의 값으로 누적
```

고차 함수는 일급 함수가 가능하기 때문에 사용할 수 있다.

# 최종 핵심 요약

```
JavaScript에서 원시 타입을 제외한 대부분은 객체이며, 함수도 객체다.

객체는 key-value 쌍으로 이루어진 프로퍼티의 집합이다.

객체는 값 자체가 아니라 참조로 다뤄진다. 그래서 객체 비교는 내용 비교가 아니라 같은 참조인지 비교한다.

네임스페이스는 전역 스코프 오염과 이름 충돌을 막기 위해 식별자들을 묶는 방법이다.

프로그래밍 패러다임은 코드를 구조화하는 사고방식이며, JavaScript는 멀티 패러다임 언어다.

함수는 재사용 가능한 코드 묶음이고, 함수 선언문, 함수 표현식, 화살표 함수로 만들 수 있다.

순수 함수는 같은 입력이면 같은 출력을 반환하고, 외부에 부수 효과를 만들지 않는 함수다.

일급 함수는 함수를 값처럼 다룰 수 있다는 뜻이다.

고차 함수는 함수를 인자로 받거나 함수를 반환하는 함수다.
```
