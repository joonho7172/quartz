**Atomic type**

경쟁 조건을 막아주고 동기화를 함. (단일 변수, 단일 상태에만 처리를 해줌, 2개의 변수를 묶어서 원자적으로 처리는 못해줌)

비관적락 -> 다른 스레드가 무조건 들어올 거 같으니까 일단 락.

낙관적락 -> 다른 스레드가 안들어올 거 같으니까 일단 연산하자. 그리고 나서 비교하자(CAS 알고리즘 ) 바뀌었으면 재시도.

값이 너무 계속 바뀌어서 계속 재시도를 하면 그건 atomictype이 적절하지 않다. (스핀락)

사용 예시

일단 int count = 0 대신에. AtomicInteger count = new AtomicInteger(0) 으로 선언.

count++ 대신에 fuel.incrementAndGet()으로 선언 해 주는 거임.

Cas(알고리즘 같은 것은 스레드에 락을 거는 것은 아님. 훨씬 빠름. )

**ReetrantLock**

Lock 인터페이스 배울 때 왜 Synchronized 대신 써야 하는지를 배웠다.

자바 레벨에서 동기화를 처리해줘야한다면 ReentrantLock을 무조건 쓴다.

정의 : 같은 스레드가 이미 획득한 락을 다시 획득할 수 있도록 허용하는 락임

- > 어떤 코드(메소드)가 이미 실행중이어도 동일한 스레드가 다시 진입해도 문제가 발생하지 않는 상태.

예시 ) 호텔 입구와 현관문을 같은 키로 연다고 하면.. 재진입 허용안하면 입구만 들어가고 현관을 들어가질 못함 -> 그래서 재진입이 필요한거임

같은 락을 요구하는 메소드에 들어가기 위해서 필요한거임. 만약에 없으면 본인이 가진 락을 본인이 기다리는 .. 메소드를 하염없이 기다리는 셀프 데드락이 걸림

즉, 여러번 락을 썻으면 내부적으로 카운터를 둬서 unlock()의 횟수까지 세서 관리함

락이나 싱크로나이즈드 걸려있는 스레드에게 인터럽트를 보내면 스레드가 무시.

그러나 -> lockinterruptibly를 사용하면 스레드는 즉시 대기를 포기하기 예외를 터트리면서 깨어남

- > 인터럽트에 반응을 하는지 안하는지에 대한 차이이다.

대표적인게 tryLock(), 그리고 lockinterruptibly() 이다. 그 외에도 당연히 몇개 더 있음.

**Reflection**

private로 선언해둔 클래스 인데 springboot에서는 객체를 안만들어도 autowired 같은 어노테이션으로 알아서 객체로 만들어줌 -> 이런게 바로 리플렉션

- >자바의 정적 타입 언어인데 이런 규칙을 우회해서 처리를 해준다 -> 프로그램이 실행 중인 런타임에 자신의 구조를 들여다 보고 조작 할 수 있게 해주는 기술. -> 동시에 위험한 기술

정의 : 클래스, 메서드, 필드 등의 정보를 실행 중에 동적으로 조회하고 조작 할 수 있게 해주는 기능

자바는 정적 타입 언어. 즉, 코드를 작성하고 컴파일 하는 순간에 100% 확정이 되어야함. -> 컴파일러가 코드를 스캔하면서 문제가 있는지 에러를 잡아줌.

그치만 유연성을 높이기 위해서 리플랙션을 사용함. 컴파일 단계에서 일단 클래스를 문자로 던지고 런타임 도중에 클래스를 알아서 찾으면 안되나.. 해서 만들어진거임.

접근 제한 된 객체에 강제로 접근 하는 경우가 있음

- > 객체지향 핵심 원칙 중 하나가 캡슐화인데.. setter메소드 안만들어도 알아서 값을 넣음.. -> 이때 리플렉션의 setAccessible 메소드가 알아서 값을 넣어주는거임 private 무력화.

WHY???

- 정해지지 않은 구조나 외부 입력에도 유연하게 대응 할 수 있는 확장성과 자동화를 위해서

주의할 점 :

일반적인 비즈니스 로직에서는 특별한 이유 아니면 쓸 일 없다. 회사에서 자체 프레임워크로 포팅해서 쓰는 거 아니면 딱히 할 일 없음.

(성능이 엄청 느림 ) 실행중에 찾아와야해서.. 그리고 컴파일 시점에 에러를 못 잡음.

결론 : 리플렉션은 정적 타입 언어인 자바가 동적으로 클래스, 메소드, 필드 정보를 조회하고 조작하는 기능.

- Class.forName, invoke, setAccessible 메소드를 통해 컴파일 시점에 알 수 없는 객체를 생성하고 제어 할 수 있다.
- 프레임 워크 기능 구현하는데 필수로 들어가지만 성능 저하와 캡슐화 파괴라는 치명적 단점이 있다.

**람다(Lambda)**
