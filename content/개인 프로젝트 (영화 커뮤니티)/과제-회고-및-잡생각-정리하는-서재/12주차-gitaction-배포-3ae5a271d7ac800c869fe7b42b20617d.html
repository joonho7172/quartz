12주차 gitAction 배포

이전 과제에서 s3와 RDS를 연동 했기 때문에, FE, BE, NGINX, 그리고 RDS쪽으로 CI를 작성했다.

기존에는 frontend 파일에 있던 nginx conf 파일이 react 화면을 제공하며, 백엔드로의 리버스 프록시 역할을 했다. 따라서 compose에는 frontend와, backend 둘에만 있었다면, 이번에는 nginx도 compose파일에 넣기 위해서 역할을 분리 했다.

외부 요청을 먼저 받는 nginx를 백엔드 폴더에 생성하고, 기존 프론트의 nginx는 정적 파일을 제공하는 용도로 나눴고, 백엔드 dockerfile에 curl를 통해 healthy 체크를 하게 해 프론트와 백 둘다 응답을 받을 수 있는 상태일때 요청을 보내도록 하였다.

Gitaction으로 aws에 배포하려면 깃헙에 aws access key나 aws access secret key를 가지고 있어야 하는데, OIDC방식으로 IAM설정하였다.

엔티티에 FE와 BE를 추가하고,

git에 action가 사용할 aws 정보를 등록한다.

permissions:
  contents: read

steps:
  - name: Checkout backend
    uses: actions/checkout@v6

  - name: Set up Java 26
    uses: actions/setup-java@v5
    with:
      distribution: temurin
      java-version: "26"

  - name: Set up Gradle
    uses: gradle/actions/setup-gradle@v6

  - name: Grant execute permission
    run: chmod +x gradlew

  - name: Build and test
    run: ./gradlew clean build --no-daemon

permissions:
  id-token: write
  contents: read

steps:
  - name: Configure temporary AWS credentials
    uses: aws-actions/configure-aws-credentials@v6
    with:
      role-to-assume: ${{ vars.AWS_ROLE_ARN }}
      aws-region: ${{ vars.AWS_REGION }}
      role-session-name: martin-backend-deploy

  - name: Deploy through AWS SSM
    shell: bash
    run: |
      set -euo pipefail

      command_id="$(
        aws ssm send-command \
          --instance-ids "${{ vars.EC2_INSTANCE_ID }}" \
          --document-name "AWS-RunShellScript" \
          --timeout-seconds 1800 \
          --comment "Deploy backend ${GITHUB_SHA}" \
          --parameters 'commands=["sudo -u ubuntu git -C /home/ubuntu/backend pull --ff-only origin main","bash /home/ubuntu/backend/deploy/deploy.sh"]' \
          --query "Command.CommandId" \
          --output text
      )"

      echo "SSM Command ID: ${command_id}"

      status="Pending"

      for attempt in $(seq 1 180); do
        status="$(
          aws ssm get-command-invocation \
            --command-id "${command_id}" \
            --instance-id "${{ vars.EC2_INSTANCE_ID }}" \
            --query "Status" \
            --output text 2>/dev/null || true
        )"

        echo "배포 상태: ${status:-Pending}"

        case "${status}" in
          Success|Failed|Cancelled|TimedOut)
            break
            ;;
        esac

        sleep 5
      done

      aws ssm get-command-invocation \
        --command-id "${command_id}" \
        --instance-id "${{ vars.EC2_INSTANCE_ID }}" \
        --query '{Status:Status,Output:StandardOutputContent,Error:StandardErrorContent}' \
        --output json

      test "${status}" = "Success"

be 워크 플로우를 작성해주고, fe 워크 플로우도 같이 작성해준다.

docker compose의 상태가 모두 healthy인것을 확인 할 수 있다.

compose는 원래 의도대로 nginx, be, fe를 담당한다.

BE와 FE 의 ACtion 둘다 성공적으로 Lint와 Build가 되었음을 확인 한다.

배포 파이프라인은 어떤식으로 구성했나요?

프론트 코드와 백엔드 코드를 별도의 git 저장소에 저장하고, 데이터베이스와 파일은 RDS와 S3를 이용해서 관리했습니다. git pull request가 올라오면, 빌드와 테스트를 자동화 해 성공 확인 후, 병합하도록 했습니다. CD 단계에서는 access key나 pem 키를 직접 git에 저장해 쓰지 않고, OIDC 공급자와 IAM 권한을 이용해 배포 스크립트를 실행 하게 하고, docker compose를 통해 fe와 be이미지를 빌드한 뒤, nginx와 함께 배포했습니다.
