1. 컴파일과 인터프리트는 프로그램을 실행하는 과정에서 어떤 차이가 있나요? 두 방식이 하나의 실행 환경에서 함께 사용될 수도 있나요?
	1. 컴파일은 컴퓨터 언어로 작성된 코드를 바이트 코드, 기계어로 번역해서 실행시키고, 인터프리트는 별도의 인터프리터가 프로그램(컴퓨터 언어)를 해석함과 동시에 실행 시킵니다.
	   기계어로 변역된 코드는 실행이 빠르지만 기계어로 변역하는데 시간이 걸리고, 인터프리트는 즉시 실행이 되지만 속도 자체는 컴파일에 비해서 느립니다. java 언어는 소스 코드를 컴파일해서 jar, class 파일과 같은 바이트 코드로 변경하고 jvm이 인터프리터 역할을 해 실행 시킵니다.


2. 정적 타입 검사와 동적 타입 검사는 어떻게 다른가요? 실행 전에 타입 검사를 통과했더라도 실행 중 타입과 관련된 문제가 발생할 수 있나요?
	1. 정적 타입 검사는 컴파일 단계에서 객체들의 타입을 미리 추론해서 타입의 일관성을 검사하는 반면, 동적 타입 검사는 런타임 단계에서 실제 값의 타입을 바탕으로 연산의 유효성을 검증합니다. 실행 전에 타입 검사를 통과했더라도, 동적으로 타입이 변경되는 경우에 런타임 오류가 발생 할 수 있습니다. 예시로는 제너릭의 타입 명시를 하지 않았거나, 상속받은 부모의 타입을 자식 타입에서 형변환하는 다운 캐스팅.

3. 제네릭은 어떤 문제를 해결하기 위한 개념인가요?
	1. 제네릭은 자료형을 매개변수처럼 받아서 같은 코드 구조를 여러 타입에 안전하게 적용하는 기능입니다.
	2. 제네릭은 같은 코드를 여러 자료형에 사용하면서 타입 안정성을 확보하기 위해 사용합니다. 
	   제네릭을 사용하는곳은 백엔드에서 응답 코드를 작성할때, 일관성과 확장성을 위해 공통 응답으로 묶을 때 사용합니다. 

4. 값에 의한 전달과 참조에 의한 전달은 어떻게 다른가요? 객체의 참조 값을 복사해서 전달하는 경우는 어느 쪽에 해당하나요? (call by reference, call by value) 좀 더 알아보기 
	1. 값에 의한 전달(call by value)는 변수에 저장된 값을 복사해서 전달하고, 참조에 의한 전달(call by reference)는 매개변수가 호출자의 변수 자체를 가르킵니다.
	2. 객체의 참조 값을 복사해서 전달하는 것은 값에 의한 전달(call by value)로, java에서 모든 인자에 적용되는 기법입니다.

5. 두 객체가 ‘같은 객체’라는 것과 ‘같은 값을 가진 객체’라는 것은 어떻게 다른가요? 객체를 비교할 때 어떤 기준을 정해야 하나요?
	1. 같은 값을 가진 객체는 서로 참조하는 객체의 주소가 달라도 그 안의 content 내용물이 같다는 뜻이고, 같은 객체 라는 것은 서로 참조하는 객체의 주소도 같다 라는 뜻입니다. 객체를 비교할 때, 그 둘의 참조 주소를 비교 하려면, "== 을 사용하고,  데이터를 비교할때는 보통 equals를 사용합니다.


6. 얕은 복사와 깊은 복사는 어떻게 다른가요? - java에서의 구현
	1. 얕은 복사는 내부 객체의 참조를 복사하고, 깊은 복사를 내부 객체 자체를 새로 복사합니다. 
	2. 예를 들어 사람이 주소를 가지고 있을때, 사람을 복사하면, 새로운 person을 만들되, 주소는 참조값만 복사합니다. 즉, 사람은 다른데 주소 객체는 같아집니다. 따라서 주소 객체를 수정하면 원본에도 반영이 됩니다. 깊은 복사는 내부 객체 (주소)도 새로 만들기 때문에 내부 객체를 수정해도 원본에 영향을 주지 않습니다.

7. 불변 데이터란 무엇이며, 여러 곳에서 같은 데이터를 사용할 때 어떤 이점이 있나요?
	1. 불변 데이터란 생성 후 내부 데이터가 바뀌지 않는 데이터를 의미하고, Java의 예시로는 Integer랑 string이 있습니다. 각각의 객체에 할당된 데이터는 바뀌지 않으며, 항상 값이 바뀐 새 객체를 생성해 반환합니다. 이러한 특성 덕분에 스레드와 같이 데이터를 공유 할때 안전하고, 캐싱과 문자열 풀이 안전합니다.

8. 클로저는 무엇인가요? 함수가 만들어질 당시의 외부 환경을 나중에도 사용할 수 있다는 것은 어떤 의미이며, 언제 유용한가요?
	1. 클로저는 내부 함수가 외부함수의 맥락에 접근할 수 있다는 뜻이고, 클로저를 사용함에 있어서, 내부 함수가 외부 함수의 지역변수를 사용 할 수 있다. 
	2. 따라서 이전에 선언한 객체의 참조를 캡쳐하는 것이기에, 나중에 실행할 작업이나 이벤트 처리를 할때, 조건을 기억하는 함수를 만들 때 유용하다.

9. 재귀로 문제를 해결할 때 종료 조건과 호출 깊이를 고려해야 하는 이유는 무엇인가요? 반복문으로 구현하는 방식과 비교해 설명해주세요.
	1. 재귀란 본인을 계속 호출해서 반복하는 알고리즘을 뜻합니다. 재귀를 호출하게 되면 java내에서 메서드 호출 스택에 매개변수, 지역변수, 복귀 위치등이 계속해서 쌓이게 됩니다. 따라서 stackOverFlow가 발생 할 수 있습니다. 반복문으로 만약 구현을 하게 된디면, 호출 스택을 계속 늘리지 않기 때문에, 재귀에 비해서 상대적으로 안전합니다. 재귀는 보통 트리 탐색 처럼 문제 구조 자체가 계층적이면 읽기 쉬운 장점이 있는 반면, 반복문은 단순 반복 작업에서의 메모리 자원을 적게 쓴다는 장점이 있습니다. 

10. 추상화와 캡슐화는 각각 어떤 문제를 해결하나요? 내부 구현을 숨기는 것과 객체의 상태를 보호하는 것을 예시로 구분해 설명해주세요. - 한번 다시 살펴보기, 정리 한번 하기 
	1. 추상화는 복잡한 구현에서 사용에 필요한 기능과 규칙만 드러낸다. 예를 들면 결제하는 쪽에서 어떤 카드로 결제하는지까지 알 필요가 없기 때문에, 결제 방식을 추상화해서 결제는 결제만 할 수 있게 내부 구현을 숨기고, 캡슐화는 객체의 상태를 정해진 규칙으로만, 검증된 메소드로만 바꿀 수 있게 함으로써 외부 코드가 객체를 잘못된 값으로 바꾸는걸 막고, 상태 변경 규칙이 여러 곳에 흩어지는 것을 방지합니다.


11. 기존 기능을 재사용할 때 상속과 합성은 어떻게 다른가요? 공통 코드가 있다는 이유만으로 상속을 선택하면 어떤 문제가 생길 수 있나요?
	1. 기존 기능을 재사용 할 때, 상속은 부모의 메소드와 상태를 그대로 물려받는 반면, 합성은 내부 객체에 기능을 위임하는데에 있어서 차이점이 있습니다. 공통코드가 있다는 이유만으로 상속을 선택하면, 강한 결합도로 인해 부모 타입의 불필요한 상태나 메소드를 물려받을 수 있습니다. 

12. 다형성은 무엇이며 같은 요청에 서로 다른 구현이 응답하도록 만드는 것이 코드 변경과 확장에 어떤 도움을 주나요?
	1. 다형성이란 같은 요청을 보내고 요청을 구현하는 객체가 달라도 되는 성질로, 상위 클래스 코드가 하나의 인터페이스만 의존하게 하면, 내부 인터페이스를 구현하는 구현체가 바뀌어도 상위 클래스 코드는 수정 할 필요가 없기 때문에 확장과 유지보수에 용이 합니다.

13. GC의 자동 메모리 관리는 더 이상 필요하지 않은 데이터를 어떻게 판단하나요? 자동으로 메모리를 회수하는 환경에서도 메모리 누수가 발생할 수 있는 이유는 무엇인가요?
	1. GC root에서 해당 객체까지 참조 경로가 남아있는지를 기준으로 판단합니다. 참조가 아예 없는 객체면 GC root가 도달하지 못하기에 회수 대상이고, 참조가 있어도 GC root가 도달 할 수 없는 경로면 회수 합니다. 참조를 기반으로 메모리를 회수하기 때문에, 현재 코드상 사용하지 않는 데이터여도 참조가 계속 지속 되면 메모리 공간을 차지하고 있기 때문이빈다. 

14. 동기 처리와 비동기 처리는 작업 완료와 다음 작업의 진행을 다루는 방식에서 어떻게 다른가요? 비동기로 처리하면 유리한 상황과 오히려 복잡해지는 상황을 설명해주세요.
	1. 동기 처리는 하던 작업이 완료가 되었을때 다음 작업을 진행하고, 비동기 처리는 하던 작업을 기다리지 않고 다음 작업을 진행하는 점에서 차이가 있습니다. 비동기로 진행하면 유리한 상황은 외부 응답을 기다리는 시간이 긴 경우, 서로 독립적인 작업이 여러개가 있는 경우가 있고 오히려 복잡해지는 상황은. 작업간에 순서의 의존성이 중요한 경우, 여러 작업이 같은 상태를 건드는 경우 꼭 동시성 문제를 해결해야합니다.

15. 동시성과 병렬성은 어떻게 다른가요?
	1. 동시성은 여러 작업이 함께 진행되도록 관리하는 것, 병렬성은 여러 작업을 같은 시점에 진행하는 것입니다. 
	2. 동시성은 네트워크나, 파일 같이 대기 시간이 긴 작업을 관리 할 때, 병렬성은 계산량이 큰 작업을 진행 할 때 주로 사용합니다. 각각의 공유 데이터에 대한 동기화 문제에도 유의해야합니다.

16. 두 작업이 공유 변수의 값을 각각 읽고 수정할 때, 실행 순서에 따라 결과가 달라질 수 있는 이유는 무엇인가요? 이런 경쟁 상태를 방지하는 방법을 설명해주세요.
	1. 두 작업이 공유 변수의 값을 읽고 수정하려고 하면, 실행 순서에 따라 두 작업의 단계가 서로 끼어들 수 있기 때문에 결과가 달라질 수 있습니다. 이러한 상황을 경쟁 상태 (race condition)이라고 하며, 갱신 손실이 일어날 수 있습니다. 이를 방지하지 위해 동기화 제어, synchronized나 atomicInteger, volatile, lock 기법을 사용 할 수 있습니다.
