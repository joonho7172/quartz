1. GET과 POST는 요청의 목적과 의미에서 어떻게 다른가요? 데이터를 조회하는 API를 POST로 구현할 수도 있다면, 어떤 이유로 선택할 수 있고 무엇을 고려해야 하나요?

2. PUT과 PATCH는 리소스를 수정하는 방식에서 어떻게 다른가요? 요청에 일부 필드가 포함되지 않았을 때 각 API가 이를 어떻게 해석해야 하는지 설명해주세요.
	1. PATCH 방식은 전체 필드의 일부분을 수정하는 방식이고, PUT은 전체 필드를 수정해 덮어씌우는 방식입니다. 
	2. 요청에 일부 필드가 포함되지 않았을 때는 정책에 따라 바뀌어야한다, 누락된 필드를 기존 값으로 유지를 한다던지, 아니면 빈값으로 돌려보낼 것인지는 문서화해서 명시해야한다. 

3. 멱등성이란 무엇이며, 같은 요청을 여러 번 보냈을 때 무엇이 같아야 하나요? 첫 번째 DELETE 요청과 두 번째 DELETE 요청의 응답 상태 코드가 달라도 멱등하다고 할 수 있나요?

4. HTTP 메서드를 PUT이나 DELETE로 지정하는 것만으로 멱등성이 보장되나요?
	1. 아니다. PUT 과 DELETE는 멱등성을 보장해야 한다는, 약속을 하는 메서드이지, 실제 구현과 동작이 이를 결정한다. 

5. 200, 202, 201, 204는 각각 어떤 상황에서 사용하는 것이 적절한가요?

6. HTTP의 4xx와 5xx 상태 코드는 어떤 기준으로 구분하나요? 요청 값이 잘못된 경우와 서버 내부 의존 시스템에 장애가 발생한 경우를 클라이언트에 어떻게 전달해야 하나요? (외부 api 응답에 대해서 생각해보기)
	1. 400 에러는 클라이언트의 오류로 잘못된 값이나, 잘못된 필드 전달 등 request에서 발생하는 오류를 나타내는 오류 코드이고, 클라이언트가 요청을 수정함으로서 해결된다. 그러나 500에러는 클라이언트의 request 자체는 유효하나, 서버가 그것을 받아들이지 못한 오류를 나타낸다. 

7. 401과 403은 어떤 차이가 있나요? 로그인하지 않은 사용자와 로그인했지만 해당 작업의 권한이 없는 사용자를 구분하는 것이 클라이언트의 후속 처리에 왜 필요한가요?

8. 프로그램 내부의 객체를 HTTP로 전달하려면 직렬화가 필요한 이유는 무엇인가요?
	1. 서버 내부의 객체, heap에 올라와잇는 객체를, 문자열이나 바이트 형태의 데이터(json, xml로 변환을 하는 과정)을 직렬화 라고 한다
	2. HTTP 전달은 네트워크 프로토콜로, 바이트 데이터만 전달이 가능하므로, 객체를 그대로 보낼 수가 없기 때문에, 직렬화가 필요하다. 
	3. HTTP 메소드 중에서 GET은 메시지 request body를 사용하지 않기 때문에, 쿼리 파라미터를 통해 직관적인 URL에 데이터를 담아 보냅니다.
