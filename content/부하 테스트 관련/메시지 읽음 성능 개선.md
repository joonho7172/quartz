## 메시지 읽음 성능 개선

`MessageReadStatusService`의 메시지별 읽음 상태 갱신을 bulk 처리로 변경했습니다.

기존:

```
메시지마다 읽음 상태 저장
→ 여러 번의 MongoDB 쓰기
```

개선:

```
메시지 ID 목록 수집
→ 한 번의 bulk update
```

또한 읽음 상태 갱신은 비동기 executor로 분리했습니다.

효과:

- 메시지 응답이 읽음 상태 저장을 기다리지 않음
- MongoDB 쓰기 요청 수 감소
- 채팅방 입장과 메시지 조회 응답 시간 단축

주의:

- 비동기 작업이 너무 많이 쌓이지 않도록 bounded executor를 사용
- 큐 대기 시간과 거부 건수는 Prometheus로 확인해야 함
