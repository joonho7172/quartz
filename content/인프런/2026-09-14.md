# 스프링 핵심 원리 기본편 1~15강 복습

## 강의 정보
- 강사: 김영한
- 사용자 수강 범위: 1~15강
- 공개 목차 기준: 자료 항목을 포함한 15번은 ‘주문과 할인 도메인 개발’이다.
- 확인한 주제: 객체 지향 설계, SOLID, 회원 및 주문·할인 도메인 예제.
- 유료 영상과 자막을 직접 확인하지 않았으며, 공개 커리큘럼과 개념 자료를 바탕으로 출제했다. 이번 3문제는 역할·구현 분리와 의존관계에 집중했으므로 전체 수강 범위의 이해도를 평가한 것은 아니다.

## 핵심 요약
- 인터페이스는 역할과 기능의 약속을 정의하고, 구현체는 실제 동작을 담당한다. 역할과 구현을 분리하면 구현 변경의 영향을 줄일 수 있다.
- 인터페이스 타입으로 선언해도 서비스 내부에서 구체 클래스를 직접 생성하면 그 구현체에도 의존한다.
- DIP는 추상화에 의존하도록 하는 원칙이다. 위반 여부는 수정할 코드의 양으로 판단하지 않는다.
- OCP는 확장에는 열려 있고 변경에는 닫혀 있어야 한다는 원칙이다. 이 예제에서는 저장소 구현을 교체할 때 기존 서비스 코드를 수정해야 하는 점이 문제다.
- 저장소 생성과 선택은 외부 구성에서 담당하고, 서비스는 필요한 객체를 전달받도록 설계할 수 있다. 생성자를 통해 전달하는 방식이 생성자 주입이다.
- Spring 컨테이너는 개발자가 작성한 생성자 등을 사용해 객체를 만들고, 설정에 따라 의존 객체를 연결한다. 생성자 자체를 만드는 것이 아니다.
- DI는 Spring 없이도 외부 구성 코드에서 객체를 생성해 전달하는 방식으로 적용할 수 있다. 이는 이번 문제를 이해하기 위한 보충 설명이며, 해당 차시 영상에서 다뤘다고 확인한 내용은 아니다.

## 문제·답변·피드백

### 1. 역할과 구현의 분리
**문제:** MemoryMemberRepository와 별도로 MemberRepository 인터페이스를 두는 이유는 무엇인가? 메모리에서 DB로 저장 방식이 바뀌는 상황을 생각해 설명하기.

**사용자 답변:**
> 인터페이스를 두고, 구현체가 인터페이스의 내부를 구현하게 하여, 역할과 구현을 분리, 나중에 유지보수성을 위해서이다

**피드백:** 핵심을 정확히 이해했다. 인터페이스가 저장·조회 기능의 약속을 정의하고 구현체가 실제 저장 방법을 담당한다고 표현하면 더 구체적이다. 인터페이스만 만든다고 모든 변경이 자동으로 격리되는 것은 아니다.

### 2. 인터페이스만 있으면 DIP를 지킬까?
**문제:** 회원 서비스 내부에 `MemberRepository repository = new MemoryMemberRepository();`가 있다. 이 구조는 DIP를 지켰는가? 이유는?

**사용자 답변:**
> 아니요, 메모리 멤버 레포지토리가 바뀔때, 예를 들면 뭐 인메모리 DB라던지 다른 방식의 repo를 참조한다고 하면 코드를 전부 바꿔야 하기 대문에 DIP를 지켰다고 볼 수 없습니다

**피드백:** 위반이라는 판단은 맞다. 다만 ‘코드를 전부 바꿔야 한다’가 아니라 ‘서비스가 구체 구현체에도 직접 의존한다’가 DIP 위반의 정확한 이유다. 한 줄만 수정하더라도 위반일 수 있다. 구현 교체 시 기존 서비스 코드 수정이 필요하다는 설명은 OCP와 연결된다.

### 3. 외부에서 객체 생성과 주입하기
**문제:** 회원 서비스가 저장소를 직접 생성하지 않으려면 누가 객체를 만들어 어떤 방식으로 전달하면 좋을까?

**사용자 답변:**
> 스프링 컨테이너가 저장소 객체를 만들고 개발자 대신 생성자 주입하면 됩니다

**피드백:** 외부에서 생성·주입한다는 방향은 맞다. ‘생성자를 만든다’는 표현은 ‘저장소 객체를 생성하고, 회원 서비스의 생성자 인자로 전달한다’로 고치면 정확하다. 컨테이너는 개발자가 지정한 구성에 따라 동작한다. Spring 없이 외부 구성 코드에서 직접 연결해도 DI다.

## 이해한 부분
- 역할과 구현 분리의 목적을 유지보수와 연결했다.
- 구현체를 직접 생성하는 구조의 변경 문제를 인식했다.
- 객체 생성과 주입을 서비스 밖으로 옮기는 방향을 제시했다.

## 다시 볼 내용
- [ ] DIP는 ‘무엇에 의존하는가’, OCP는 ‘확장 시 기존 코드를 수정해야 하는가’로 구분해 설명하기.
- [ ] 생성자와 객체를 구분하기: 생성자는 객체를 초기화할 때 호출되는 클래스의 구성 요소다.
- [ ] Spring 없이도 외부에서 객체를 만들어 전달할 수 있음을 설명하기.

다음 복습 후보: ‘인터페이스 타입을 사용하지만 서비스가 구현체를 직접 생성한다면, 수정할 곳이 한 줄뿐이어도 DIP 위반일까? 왜 그럴까?’
