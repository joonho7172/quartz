올바른 객체 지향 설계의 SOLID 원칙, SRP, OCP, LSP, ISP, DIP 원칙

SRP - 단일 책임 원칙 (하나의 클래스에는 하나의 책임만 가져야 하며, 클래스가 바뀌는 이유도 단 하나여야 한다.)
OCP - 개방 폐쇄 원칙 (확장에는 열려 있어야 하고, 수정에는 닫혀있어야 한다.) 
- 즉 기존 코드를 수정하지 않고 변경이 가능해야한다.
LSP - 리스코프 치환 원칙 (자식 클래스는 부모 클래스를 대체 할 수 있어야 한다.)
- 하위 클래스가 상위 클래스가 물려준 메소드나 의도를 깨지 않아야 한다.
- 예시로) bird의 fly를 penguin이 물려받을 수 없는 것 처럼.
ISP - 인터페이스 분리 원칙 (자신이 사용하지 않은 메소드에 의존하지 않아야 한다.)
- 여러 개를 하나에 몰아넣지 않는다.
- 예시로) 주방에서 칼과 주걱, 수저들은 분리하는 것 처럼 별도로 분리를 해야한다는 것.
DIP - 의존 역전 원칙 (변화하지 않는 추상화에 의존 해야한다.)
- 고수준 모듈이나 인터페이스에 의존해야한다.

이러한 객체 지향 설계를 해주는 가이드라인을 제공하는 것이 Spring이다. 
Spring 이 [[DI]]나 [[IoC]]를 통해서 객체를 생성해 등록하고 주입해주는데, Spring 없이 개발을 진행을 해보며 필요성을 깨달아보자.

AppConfig 를 통해서 설정을 해보고, 가짜 Spring 컨테이너를 만들어서 생성자 주입을 해보기.
memberRepositoryImp에서 inMemoryRepository인지, dbRepository인지 직접 설정을 하고, 상위 모듈은 구현이 아닌 역할에만 의존하게 해서 설정을 한다.
