클린코드는 잘 짜인 산문 처럼 읽힌다.. 왜? 산문은 문장과 문단으로 구분되는 것처럼 코드도 함수와 모듈로 구분이 되어 있기 때문. , 물론 코드 자체가 프로그래머에게 소설과 같진 않지만, 적어도 기본기만 아는 사람에게도 쉽게 읽힐 수 있어야 한다. 코드를 잘 짜고, 클린하게 짜는 것 자체가 개발 속도의 지연과 연관이 있다.

코드를 잘 짜야 하는 이유
1. **생산성**
	1. 다른 이들의 속도까지 늦추지 마라. 코드를 정리하는 단 한 번의 시간이, 훗날 일으킬 반복될 시간을 절약 시킨다.
2. **코드의 읽는 시간이 짜는 시간보다 길다**
	1. 결국 이전과 일관된 코드를 짜야 하기에, 기존의 코드를 읽는 시간이 새로운 코드를 짜는 시간보다 길 수 밖에 없다. 읽는 시간과 이해하는 시간을 절약 하기 위해서라도 코드는 클린하게.

켄트 백
```
먼저 돌아가게 만들라, 그런 다음 제대로 만들라
```
ai시대에 와서 더 중요하게 여겨지는 역량이 ai가 제공한 코드가 과연 양질의 코드인지 판단 할 수 있어야 하는 것.
즉, 결과물을 판단하기 위해서 프로그래머들은 꾸준히 노력해야 한다. 

### 어떻게 클린코드를 작성하는가?

*모든 것을 작게, 잘 명명하고, 체계화 하며, 정렬하자*
작게 : 다른 프로그래머들에게 의미를 전달할 수 있는 이름을 붙여라
쳬계화 : 쉽게 사용할 수 있도록 구조와 체계를 정의하고 유지하자
정렬 : 각 요소들이 합리적이고 상식적인 순서로 이어지도록 잘 정렬하자


코드가 늘어날 것 같거나 정책이 추가 될 것 같으면, 하나의 함수에 때려넣는것이 아닌, 단일 책임 원칙을 지켜서 변경에 유연해질 것.
