동기 / 비동기

동기는 한 작업이 끝날때까지 다음 작업으로 넘어가지 않는 방식 -> 전체가 밀릴 가능성이 있음.

비동기는 오래 걸리는 작업을 별도의 흐름으로 넘김. 현재 흐름은 다음 일을 계속 처리하는 방식.

—> 지금 반드시 끝나냐 하는건 동기, 나중에도 가능한건 비동기로 나누면 됨

- > 스레드는 이 판단을 코드로 구현하기 위한 기초 작업이라고 생각하면 됨

**공유 변수와 메모리 가시성 문제**

동시성

- > 여러 작업이 겹쳐서 진행되는 상황. 여러 작업을 빠르게 번갈아서 하기 때문에 동시에 실행되는 것처럼 보인다.
- > 여러 실행 흐름이 같은 시간대에 존재한다.
- > 문제는 각자 독립적인 데이터만 다룰때만 안전하다. 같은 데이터를 함께 건드릴때 부터 문제가 생김
- > 여러 스레드가 같은 count 변수를 증가 시키거나 같은 arraylist에 데이터를 추가하거나 같은 파일에 공유 자원 접근
- >실행 순서가 조금만 달라져도 결과가 달라짐 -> race condition -> 두개의 스레드가 하나의 값에 동시에 count++를 실행하면 실제로 한번만 증가한 것 처럼 보일 수 있다.

따라서 여러 스레드가 공유 자원에 접근하는 순서를 조절함

- > 제일 쉬운건 동기화 synchronized

결론

- 스레드 사용하면 여러 실행 흐름이 생기는데 이들이 같은 데이터를 만지면 문제가 생김 이를 해결하기 위한게 동기화.

**Runnable**

쓰레드가 실제로 실행 작업을 분리해서 정의하는게 대표적으로 runnable 인터페이스

클래스 상속 받는것보다 작업명세의 분리와 클래스의 역할 분리를 위해서 runnable인터페이스를 많이 씀.

Why?? — runnable 구조의 이점이 있음.

1. 작업과 실행 주체를 분리를 함
2. runnable로 구현하면 클래스는 작업이 된다.
3. 같은 작업을 여러 스레드에 적용 시킬 수 있음.(코드 재사용성)
4. 불필요한 상속들을 안받을 수 있다.
5. 스레드 클래스를 상속받으면 다른 클래스를 상속받질 못함.

결론

- runnable은 실행 할 작업을 독립된 객체로 정의하는 표준 타입.
- run()메소드에 실행 코드를 담고 thread나 executor service같은 주체가 호출 한다.
- Runnable 통해서 작업과 실행 제어 분리를 한다.

**Executor Service**

스레드랑 러너블 보면서 작업을 별도 실행흐름으로 분리 -> 스레드 관리 비용이 많이 들어감 -> 그래서 직접 스레드를 다루지 않고 executor service한테 맡긴다.

스레드 풀 기반임 -> 스레드를 매번 새로 만들지 않고 미리 만들어둔 스레드를 재사용함

비동기 작업 실행. -> 요청한 코드가 끝날때까지 이 자리에서 계속 기다리지 않음

고수준 -> 스레드 생성하고 재사용, 종료 같은 복잡한 수준을 추상화 해주고 제공해줌.

유의점 : 사용하지 않으면 리소스 회수를 위해서 종료를 꼭 해줘야됨

Why?? - 스레드를 직접 관리하지 않고도 대량 작업을 안전하게 병렬작업

1. 시스템 자원을 예측 가능하게 제어.

**Thread Pool**

자바에서 스레드, 러너블, 익스큐터서비스 중.

작업개수가 많아질때 서버가 뻗어버리는 일이 있다. -> 스레드 풀을 이해하고 있으면 해결하기 원활함

결국 스레드 풀과 엑시큐터 서비스와의 관계는?

- > 엑시큐터는 작업 실행을 관리하는 고수준의 인터페이스임

Why?? - 스레드 수 제한. 시스템 자원을 예측 가능하게.

1. 풀 크기와 작업 큐를 통해 갑작스러운 요청 증가 상황에서도 처리량을 조절하고 시스템을 보호 할 수 있음.

어필리케이션이 호출을 하면 -> Task Queue에 저장 -> 그 다음에 엑시큐터가 기준에 따라 작업을 처리

큐의 크기는 어떻게 해야하는 가? ->

너무 크게는 하면 안됨 처리속도보다 요청속도가 더 빠르면 그거대로 문제이기 때문에.

결론

- 스레드 풀은 작업을 안전하게 받고 제한된 수의 스레드를 실행하고 다시 재사용하는 모델
- 재사용해서 자원 낭비 줄이고 동시에 실행되는 작업량 안정적으로 제어하기 위한 구조

**Synchronized**

여러 스레드가 동시에 공유 자원에 접근하지 못하도록 하는 동기화 키워드임.

수업에서의 핵심

1. Runnable은 실행할 작업, 스레드는 그 작업을 실행하는 주체
2. 실제로 일할 때는 runnable로 정의하고 실행 관리는 Executor Service에 맡기는 경우가 많다.
3. Executor service는 작업과 스레드 실행 관리를 분석해주는 실행 서비스이다.
4. execute(), submit() 둘 다 작업을 제출하는데에 결과와 예외 추적에서 차이가 있음
5. Executor service는 반드시 종료 시켜줘야함.
6. 스레드 풀은 스레드를 새로 만들고 버리는 비용을 줄이기 위한 구조이다.
7. 스레드 풀은 작업 큐, 유휴 스레드, 풀 사이즈 등을 같이 이해 해야한다.
8. Synchronized 는 공유 자원에 접근하는 영역을 한번에 하나의 스레드만 실행되도록 제한한다.
9. Synchronized 메소드, 클래스, 변수 어디에 쓰느냐에 따라 다르다.
10. 동기화는 정확성을 높이지만 임계 영역을 잘못 잡으면 데드락,
