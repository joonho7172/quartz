스킬이 보존하고 관리하는건 일하는 방법 자체.
특정 작업에서 반복해서 필요한 지식, 절차, 참고 자료, 템플릿, 선택적 스크립트를 하나의 재사용 가능한 단위로 구성한 agent 기능

반복 -> 스킬이 한번 하고 끝나는 작업이 아니라 여러번 재사용 할 수 있는 것
단위 -> 작업하는 과정에서 절차 하나만 다루는 게 아니라 절차에 필요한 템플릿, 검증 스크립트까지 하나의 디렉터리로 묶을 수 있다.

클로드 코드에는 클로드 리뷰랑 심플리파이 라는 스킬이 처음부터 들어있음.
anthropic이 자기팀에서 실제로 쓰는 코드 리뷰 기준을 그대로 옮겨 놓은 것.
-커밋전에 변경 사항 점검이나 이런것들..

스킬이 있다는건 일정하개ㅔ 관리를 한다는 것.
일종의 작업 절차에 대한 규율과도 같음.

같은 순서로 계속 반복하는 작업이 생기는데 이것들은 skill로 옮기는 것을 고려 해봐야함.
객체 지향과는 좀 다른 이야기..
범위 작성도 하면 좋음. 언제 선택하지 않아야 하는지 판단하는

agent.md에 너무 많이 넣으면 컨텍스트 낭비고..
프롬포트 에다가 절차 매번 넣는 것도 낭비임.
작업 할 때마다 써야 해서.. 
스킬은 agent.md랑 프롬프트 직접 작성하는 것의 중간 지점에 있음
- 항상 필요한 프로젝트의 공통 규칙은 agent.md에 두고 특정 작업에 필요한 반복 상세 절차가 있으면 그때 skill로 분리를 하는 것 임.

skill-creator라는 스킬이 있음.
- 당장에 코덱스나 이런데에다가 스킬 목록 물어봐도 됨
- 그리고 트리거 설정은 필수 알맞는 프롬프트에 알맞는 스킬이 적용되게

단순히 프롬포트 와 agent.md, memories에 두고 작업하는 것을 알아볼 것.
모든 작업 필요한 공통 규칙 -> agent.md
한건의 요청 -> prompt
과거 작업에서의 사실이나 진행 -> memory
특정 종류의 작업에서 반복되는 절차 -> skill

정리
* 스킬은 반복 작업의 절차랑 판단 기준이랑 검증 스크립트를 하나의 재사용 단위로 묶은 기능.
* 모든 작업에 필요한 공통 사항은 에이전트 .md 한건의 요청은 프롬프트, 특정 작업이나 반복되는 작업은 skill.
* 스킬은 점진적으로 load된다. description에 트리거 조건 명시해두고 세부적인 것은 별도의 레퍼런스 파일로 해서 호출하게 해라
	* 트리거랑 논트리거 나눠서 디스크립션에 잘 명시하는게 중요함.
