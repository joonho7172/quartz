abortController - posts 게시글을 불러올때, 응답 전에 다른 페이지로 이동하면 기존의 컴포넌트를 제거하는 것으로, 

post id 1을 조회하자마자 post id 2를 조회했는데 post id 1 게시글 응답이 느려서, 현재 url은 post id 2인데 post id 1 화면이 나오는 문제점, race condition이 일어날 수 있음을 알았다. 다만, abortController는 사용자가 브라우저 응답을 기다리는것을 막는 것이지 이미 시작된 작업까지 반드시 취소하는 것은 아니라는 것을 유의해야 한다고 배웠다.

## 6

페이지 상세구현에서 댓글 수를 보여주는 과정에, 

```jsx
  const displayedCommentCount = commentsHaveLoaded
    ? comments.length
    : post?.commentCount ?? 0;
```

ai는 comments를 어차피 List로 가져오기 때문에 length 로 댓글 수를 가져왔다.

내 postResponse에는 백엔드에서 구현한 select*을 해서 가져온 commentCount가 있는데 사용하지 않는 이유에 대해서 알아보았다. 이유는 단순하게, 내 백엔드 api에서는 commentCount를 댓글 수정, 삭제가 반영되지 않기 때문이었다. 댓글 api는 새로운 commentResponse를 가져오기 때문에 즉시 반영과 렌더링이 되지 않은 이유 였다. 추가적인 state 없이 length만 가져오면 돼서 간편해 보였다. 만약 내 postResponse에서의 commentCount를 가져와서 굳이 쓰겠다고 하면 updateCommentCount function을 추가해서, 추가, 삭제 될 때마다 값을 바꿔 주는 방법이 있다. 그렇게 되면 hasLoaded state를 사용하지 않을 수 있고, 나중에 페이지네이션 적용에도 전체적 commentCount를 가져오기 때문에 데이터 정합성에도 좋다는 것이다.

length 는 단순하고 편리하지만 댓글 페이지 네이션을 적용하면 당장 보이는 comment의 갯수만 보여주는 치명적 단점이 있기에, 결국 두번째 방법으로 가기로 했다.

사실은 이 모든게 내 api에서 postResponse는 commentCount를 반환하는데 commentResponse는 Count를 반환하지 않기 때문에 생긴 일들 인 것 같다..

사실 프론트에서 삭제하면 -1, 추가하면 +1 해서 계산하는 방법도 나쁘진 않아보이는데

## 7

useComments에서 commentText를 state 관리하는데,

사용자가 입력하는 textArea쪽은 useRef로 관리하는게 낫지 않나? 굳이 state로 관리해서 매번 재렌더링은 성능에 안좋지 않나? 라고 생각했다.

사용자가 키보드 입력
→ textarea onChange 실행
→ changeCommentText("안녕")
→ setCommentText("안녕")
→ commentText state 변경
→ PostPage 다시 렌더링
→ CommentForm에 value="안녕" 전달
→ textarea에 "안녕" 출력

현재 상태 변화. 순서만 보면 매번 입력할 때마다 성능 저하가 있을 것 같지만 아니었다.

애초에 리액트 vdom기능도 있고 글자 하나가 이미지를 바꾸는 것도, post전체를 리렌더링 하는것도 아니고 입력필드가 여러개 있는 것도 아니므로 별 다른 성능 저하가 없다고 AI는 판단하는 것 같았다.

다만 state로 관리하면 댓글이 비어있을때의 오류나, 버튼의 보이는 상황을 직접 인지 할 수 있기 때문에 textarea를 state로 관리하는 것이 흔한 일이라고도 했다. 그래서 결국에는 state값을 유지하되,

렌더링 범위를 줄이기 위해서 useComments 내부의 state관리를 CommentForm내부로 바꿔서 postPage의 게시글 본문과 댓글 목록은 영향을 덜 받게끔 수정했습니다.

이번 마이그레이션을 통해 Vanilla JavaScript와 React의 차이를 이해할 수 있었습니다. 기존에는 querySelector로 HTML 요소를 찾고 DOM을 직접 변경했지만, React에서는 props와 state를 중심으로 화면을 관리하며 상태가 변경되면 UI가 자동으로 다시 렌더링됩니다. 또한 화면은 컴포넌트로, 공통 기능과 상태 로직은 Custom Hook으로 분리하면서 책임이 명확해졌고 코드의 재사용성과 유지보수성도 향상 되었음을 체감했습니다.
