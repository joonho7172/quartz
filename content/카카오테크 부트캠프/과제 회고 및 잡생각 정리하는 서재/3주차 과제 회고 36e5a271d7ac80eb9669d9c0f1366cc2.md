postid 같은 경우는 필수로 있어야하는 값, 특정해줘야 하는 고유값 이길래 {}를 통해 감싸줬다.

게시글 목록 조회도 처음에는 /posts로 했다가 10개씩 나오게 하는 명세를 보고 size를 10으로 조절했다.

page로 나누고 size만큼 목록을 띄우는데 인피니티 스크롤은 어떻게 해야 할지 몰라서 일단 page로 나누었다.

개인정보 수정에서 닉네임 같이 민감하지 않은 정보는 users/users-id 에서 찾아올 수 있지만

민감한 개인정보는 db에 저장하지 않는다고 들어, 비밀번호 수정은 users/users-id에서 가져오지 못할것 같아 api작성에 궁금증이 생겼다.

질문

1. 페이지 별로 , 게시글 수를 적는 api는 알겠는데 인피니티 스크롤은 api 방법이 다른가요?
2. 비밀번호 같은 민감 정보는 db에 저장하지 않는다고 수업에서 들은 적이 있고, api를 작성이 가능한건가요? (만약에 있다면 비밀번호 말고 이메일이나 아이디, 등 어느정도 민감한 정보이나 비밀번호 정도는 아닌. 정보들도 api 작성에 차별점이 있나요?)
3. 좋아요 같은 개념은 한 사용자의 관점에서는 누를 때마다 좋아요, 좋아요 취소 가 반복되므로 토클 형식으로 PATCH 로 두어도 될 것 같은데, 전체 시스템 관점으로는 POST와 DELETE가 반복 되는 것 같습니다.         그래서 POST와 DELETE 로 구분하려고 하였으나, 좋아요의 내용이 있는 것도 아니고, 갯수만 +1, -1 하는 것이라 POST와 DELETE의 목적이 아닌 것 같아 PATCH 하나로 설정했습니다. 제가 맞게 생각 한 것인지 확인 받고 싶습니다 (만약에 맞다면 body의 구성이 어떻게 되는지 궁금합니다.)
4. 로그 아웃 개념은 감이 아예 안잡혀 ai의 도움을 받았습니다. 대충 로그 아웃은 post(서버의 상태 변경), 또는 delete(세션이나 토큰 만료 시키기) 라는 답변을 받았는데 가이드 조금만 주시면 찾아보겠습니다.!
