# 7주차 과제 회고

전체적인 fetch는 초반에 구상했다. api를 가져올때 비동기 작업 처리를 위해 async , await를 사용해 가져오는 response를 처리했고, POST 나 PUT, PATCH 처럼 body가 있으면, method로 정의, header에 Content_type을 json으로 맞추고, 객체 상태로 HTTP요청을 하지 못하기에, body.stringfy를 통해 문자열로 변환해 요청을 보냈다. 반환되는 json을 js에서 사용하기 위해서 result를 사용해 response울 다시 정의하고, 

result를 반환하는 것을 요청-응답 기본 뼈대로 설정하였다.

js를 이렇게까지 다뤄 본 적은 한번도 없어 맨땅에 헤딩하다가 쓰러질 것 같아 월요일 부터 ai를 주로 사용했습니다. fetch 사용 부분은 기본 뼈대를 구상해놔서 ai에게 자아를 의탁하지 않고 주도적으로 할 수 있었는데 그 외 render나 다른 function들은 제로에서 시작하기가 너무 어려워 ai에게 작성 예시 코드를 보여달라고 요청했습니다.. 필요없는 기능이나, 아래 post쪽에서의 CommentCount처럼 비효율적 로직은 수정을 하긴 했으나 상당 부분 ai에게 부탁한 것 같습니다..

# Posts

우선 게시글을 백엔드 api에서 불러 들여하기 때문에 관련 메소드를 하나,

가져온 posts를 카드로 보이기 위한 메소드 하나,

보이는 카드를 post 상세 조회로 이동하기 위한 메소드 하나로 생각했다.

posts카드를 만들고 반환하는 함수에서는, 버튼을 눌렀을 때 상세 조회로 이동하기 위해서 이벤트 리스너를 추가, 눌렀을 때 경로를 상세 조회 경로로 이동하게 하였다. 

이 둘을 합쳐서, api 백엔드에서 List값으로 getPosts를 조회하니, posts를 배열로 받고, 만약 배열의 길이가 0(게시글이 없으면) 등록된 게시글 없다고 반환, 만약 게시글이 있으면 각각의 배열에 있는 post들을 createPostCard로 넘겼다. 

만들어진 PostCard를 붙이기 위해 Ai에게 질문 하였고 PostCard를 PostList라는 부모에 appendChild 문법으로 자식으로 넣어서 보여주라는 답변을 받았다. 

그 후 loadPost를 통해 목록 표시 및 오류 확인.

# Post

게시글 상세 조회 페이지

크게 구현해야 할 기능은 1. 게시글 불러오기, 2. 댓글 불러오기, 3. 댓글 작성하기, 4. 게시글 수정하기, 5. 댓글 수정하기. 6. 게시글 삭제하기, 7. 댓글 삭제하기 였다. 

게시글 수정하기와 댓글 수정하기 같은 경우는 백엔드 api에서도 isWritten() 메소드를 사용해 억지로 다른 사용자가 보내는 수정 요청에 차단 했지만, 프론트에서도 id를 비교하여 작성자가 아니면 수정 버튼과 삭제 버튼이 보이지 않도록 설정했다.

Comment를 render 할때, 어떻게 시작해야 할지 몰라 ai에게 renderComments 함수의 예시를 보여 달라고 아예 요청 하였다.

백엔드 api에서 comments를 get 요청하면 list 배열로 반환하는데, comment의 개수를 list.length()로 조회해서 가져오고 있었다. 갯수만 알면 되는데 comment의 정보를 모두 가져오고 length로 갯수를 세는게 효율적이지 못한 것 같아서, 

commentRepository에 countByPost_Id 메소드를 추가해서 가져오기로 변경 했다.

# PasswordEdit

초기에 백엔드 api에 비밀번호를 입력 받는 dto를 따로 만들지 않았어서 명세를 따라가는데 어려움이 있었다. 

결국 api에서 비밀번호 수정에 관련된 updatepassword 요청을 받고, 

전체적인 result 구상과 같이 api를 통해 요청하고 반환 값을 담으려 했다. 

프론트에서 변경할 비밀번호와, 비밀번호 확인을 confirm하는 passwordConfirmHelper 객체를 만들고, 

각각의 오류(비밀번호 입력을 안함, 비밀번호 확인 칸을 공백으로 냄)등에 관한 문구를 출력하는 validate 함수를 만들었다.

그 후 비밀번호 변경 함수는 기초 뼈대를 기반으로 async await로 fetch 요청을 보내고 결과 result를 반환 했다.

비밀번호 변경이 성공하면 localstorage.clear와 함께 초기 로그인 화면으로.

기존에 비밀번호를 확인 받는 것도 아닌, 바로 비밀 번호 변경 페이지에서 비밀번호를 변경 할 수 있게 되어있어 어렵지 않았다.

프론트에서 한번 비밀번호 검증을 거치지만 백엔드 api에서는 입력받은 2개의 문자열을 비교하는게 없어 나중에 추가 해야 할 것 같다…
