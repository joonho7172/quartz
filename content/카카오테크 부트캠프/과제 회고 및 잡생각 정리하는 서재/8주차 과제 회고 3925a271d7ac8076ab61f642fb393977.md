@RequiredArgsConstructor와 @Autowired의 차이점

1. autowired 필드 주입 같은 경우는 필드를 먼저 만들고 spring container에서 bean을 주입하기 때문에 final 사용 불가 / RequiredArgsConstrutor는 생성자가 주입 받는 도중에 바뀌는 것 방지.
2. 순환 참조 방지. / autowired는 일단 객체를 만들고 주입하기 때문에 명확하지 않지만 RequiredArgsConstructor는 객체를 만들 때 생성자를 주입하기 때문에 순환참조 명확
3. 테스트 코드의 차이. 
    1. (autowired는 spring이 돌아가야만 필드 주입으로 테스트 가능)
    2. autowired 같은 경우는 스프링이 필드에서 주입하므로, userService에서 userRepository를 주입하려면 spring이 필수이다. 만약 억지로 userService()를  만들었다가는 스프링이 repository를 주입해 주지 않아서 userRepository가 null값임.
    3. RequiredArgsConstructor 는 처음부터 userService(userRepository)가 만들어지므로 테스트 할 때 불완전한 userService가 만들어질 수 없음. → userRepository를 mock으로 대체해서 주입 가능

# 테스트 코드 (하다보니 user 도메인 외 다른 도메인도 했습니다)

먼저 userService에 대한 테스트 코드 회고이다.

1. Repository에 잘 접근하는지 (회원가입, 로그인)
2. 회원가입 할 때 설정한 비밀번호 조건 잘 되는지 - controller에서 valid로 검사하는 값이라 controller 테스트에 넣어야 할 것 같다.
3. 회원 가입 할 때 이메일 중복 체크가 잘 되는지
4. 회원 가입 할 때 사용자 이름(닉네임) 중복 체크가 잘 되는지
5. 로그인이 잘 되는지 (accessToken 잘 돌려주는지)
6. 회원 탈퇴가 잘 되는지 (탈퇴 후 같은 이메일, 닉네임으로 가입)
7. 회원 닉네임 수정과 비밀번호 수정이 잘 되는지

그리고 PostService에 대한 테스트 코드 회고

1. repository에 잘 접근해서 값을 가져오는지, (게시글 목록, 게시글 상세 조회)
2. 게시글 작성이 잘 되는지. (내용과 제목이 잘 들어가는지)
3. 수정이 잘 되는지. (본인의 글에만 수정이 되는지, 인가가 되면 제대로 작동하는지 )
4. 좋아요가 잘 눌리는지. (본인이 누른 좋아요와 그에 대한 좋아요 취소)
5. 게시글 삭제가 잘 되는지(본인이 작성한 글에만 삭제)

그리고 commentService에 대한 테스트 코드 회고

1. repository에 접근해서 댓글 목록을 잘 불러오는지,
2. 댓글 작성이 잘 되는지 (사용자랑 게시글이 있거나 없을때는?)
3. 댓글 수정이 잘 되는지 (작성한 사용자만 수정 가능)
4. 댓글 삭제가 잘 되는지 (작성한 사용자만 삭제 가능)
