Docker compose 는 필요한 여러 컨테이너를 하나의 yaml 파일로 정의해서 실행하게 해주는 것. 여기서 react의 app, redis같은 비동기 메시지큐, database, nginx 같은 컨테이너를 각각 따로 실행하지 않고 파일 하나에 선언해서 실행 하는 것. 하지만 그래도 직접 EC2에 접속해서 명령어로 입력하는 수동 배포이기 때문에..

CI/CD가 탄생 CI는 Continuous Integration (지속적 통합) - 개발자가 코드를 합치고, 빌드와 테스트를 자동으로 돌려 문제가 없는지 확인 CD - Continuous Delivery 또는 Deployment 로 검증된 배포물을 배포 가능한 상태로 만들어주는 것.

git action같이 push 하면 workflow가 일어나는데, 코드를 체크아웃 → 테스트 → Docker 이미지를 만들고 → Registry에 push → EC2가 새로운 이미지를 pull 해서 → 컨테이너를 띄우는  형식이 자동으로 일어남

(핵심은 사람이 명령어를 치는게 아니다.. )

사용자 경험을 좋게 하기 위한 무중단 배포 bluegreen 배포도 있음.

devops 같은 경우는 개발과 운영을 연결하는 작업 문화를 이야기 함. 개발팀과 운영팀이 나뉘어져 생기는 소통 문제, 책임 분산, 문제 해결, 장애 대응을 좀 줄이기 위한 개발 방식. 이 흐름에 CI/CD, Docker, IaC가 있다. 

EC2 같은 경우는 running 상태에서부터 비용이 발생함 terminate 전까지는 비용이 계속 발생 함.

보통 중지 했다가 다시 실행하면 public ip는 변경된다. private ip는 변경되지 않음 (이걸 해결하는게 elastic ip)

IAM 같은 경우는 AWS에서 EC2를 만들거나 종료할 권한을 따지는게 IAM

주요 구성 요소로는 사용자, 그룹, 역할, 정책

**VPC (Virtual private cloud**

VPC는 Virtual Private Cloud의 약자로, AWS 클라우드 안에 만드는 나만의 논리적으로 격리된 네트워크 공간이다.

VPC를 만들때 IP 주소 범위를 정하는데, 이 범위를 퍼블릭 서브넷과 프라이빗 서브넷으로 나눔. 

퍼블릭 서브넷은 인터넷 게이트웨이로 나가는 route가 있는 서브넷이다

프라이빗 서브넷은 인터넷 게이트웨이로 나가지 않는 서브넷. (보통 DB, 내부 API, 캐시 서버 같은 것을 프라이빗 서브넷에 둔다.)

그러면 프라이빗 서브넷은 밖으로 못나가냐? (외부 api 호출 목적으로) ㄴㄴ  그걸 해주는게 NAT 게이트웨이, 그러나 이거는 외부에서 들어오는걸 허용하지 않음. 프라이빗 서브넷이 나가는것만을 도와줌

추가적으로 라우트 테이블 같은거는 **목적지 IP 대역별로 트래픽을 어디로 보낼지 적어둔 표다.**
