**Database**

정의

데이터베이스는 단순히 데이터 저장하는 공간이 아니라 체계적인 구조(스키마)를 갖고 데이터를 저장함.

사용 이유

데이터를 테이블 체계로 저장하며, 데이터의 안정성과 신뢰성을 보장하기 위해서

1. 데이터의 영속성, 안전성

스프링 개발 했다고 하면 변수나 객체는 메모리에 저장이 됨. -> 휘발성 데이터 이기 때문에 서버가 다운되면 데이터가 사라짐.

- > 데이터 베이스는 HDD나 SSD에 저장해서 사라지지 않음.
1. 데이터의 무결성, 신뢰성

데이터가 맞는 도메인의 타입만 입력 받음. 항상 데이터가 깨끗하고 정확한 상태로 유지됨

1. 데이터의 동시 접근 및 공유

데이터베이스는 트랜잭션이나 락을 통해서 데이터 무결성과 동시성을 확보함.

데이터 중복도 막고, 갱신이상도 막을 수 있음.

어떻게? 고유한 index 부여 해서 각 상품을 구별하는 유일한 값으로 관리함.

아예 인식 시킬 수 있는건 PK, 다른 테이블의 기본키를 참조하는 값이 (FK),

스키마

테이블 구조와 데이터 타입을 볼 때 생각해야 할 관점.

서버에서 user 테이블의 email과 컬럼은 문자열이고 비어있지 않고 중복되지 않는다 라는 전제가 있어야 하듯이..

- > 근데 이런 전제는 코드만으로 지켜지지 않음. 따라서 Not ull, unique, foreign key, 데이터 타입 같은 규칙이 있어야 함. 이런 규칙이 스키마이다.

관계데이터베이스가 중요함

정리 :

- 데이터베이스는 구조화 된 데이터 모음, 데이터를 정보로 활용하기 위해서 사용함
- 데이터의 영속성, 무결성, 동시성을 보장하기 위해 데이터 베이스 쓴다.
- RDB 같은 경우 데이터를 테이블 단위로 저장하고 기본키와 외래키 이용해서 테이블 간 관계를 맺는다.
- DBMS

**정규화**

정규화는 좋은 원칙이지만 절대적으로 지켜지지는 않는다. 비즈니스 상황에 따라서는 타협하는 경우가 있음.

- > 회사에서 설계 리뷰 하다가 안지켜지는 경우도 솔직히 있음.

정의 : 관계형 데이터베이스의 설계에서 중복을 줄이기 위해 테이블의 책임을 나누는 과정

1. 중복의 최소화

데이터 중복되면 저장공간 낭비 됨. 데이터 불일치 또한 유발.

어떤 고객의 주소 정보가 여러 곳에 중복 저장이 되어있다고 가정

- >한 곳이라도 놓치면 나머지 데이터들이 불일치됨.

정규화는 이런 문제를 원천적으로 차단하기 위해서 데이터가 한곳에 저장되도록 구조를 개선한다.

1. 데이터 구조화

정규화는 단순히 데이터 나누는 과정이 아니라 ‘함수적 종속성’이라는 근거에 따라서 데이터의 관계를 명확하게 파악하고 그에 맞는 테이블을 재구성 하는 과정이다.

사용 이유

무결성을 유지하고 저장 용량을 줄이기 위해서

- > 정규화를 하는 근본적인 이유는 데이터 이상 현상을 막기 위해

갱신이상, 삭제이상, 삽입이상이 있을 수 있음.

**제 1 정규형(1NF)**

정의 : 테이블의 모든 컬럼은 반드시 원자값을 가져야 한다.

원자값 : 더이상 쪼갤 수 없는 값 -> 하나의 컬럼에는 딱 하나의 데이터만 들어가야한다는 단순한 규칙

**제 2 정규형(2NF)**

정의 : 1정규형 만족, 기본 키의 일부가 아닌 모든 컬럼은 기본 키 전체에 완전 함수 종족이어야함.

(부분 함수 종속이면.. 기본키가 2개 가 되는 복합키에서 일부분만 특정 기본키에 완전 함수 정족 하는거임

수강 테이블의 모든 일반 컬럼은 기본키 전체에 완전하게 종속이 됨.

과목 테이블의 일반 컬럼 과목 ID에 완전 종속이 된다.

**제 3 정규형(3NF)**

정의 : 2정규형 만족하고 부분 이행 종속을 하지 않아야 함.

이행 종속 : a->b b->c면 a->c이다.

- 일반 컬럼끼리 종속 관계가 발생하는 것을 막는 것이 3NF의 목표.

예시 : 컬럼안에 사원번호, 사원명, 부서번호, 부서명, 부서위치.. 이렇게 잇으면

그냥 사원 테이블, 부서 테이블. 이렇게 나누면 되는 거임.

**반정규화**

정규화 데이터의 무결성을 지키는 원칙

- > 정규화를 통해서 테이블을 잘게 쪼개다 보면 원하는 데이터를 얻기 위해 여러 테이블을 연결하는 join을 사용해야함.
- > 조회 성능이 떨어질수도 있음.

즉, 의도적으로 정규화 원칙을 위배해 조회 성능을 높임.

**SQL**

정의 데이터 베이스 시스템에서 자료를 처리하는 용도로 사용되는 구조적 데이터 질의 언어

- >sql은 선언형 언어
- > 우리가 데이터 베이스에 무엇을 원하는지 말하면 어떻게 그 작업을 수행할지는 DBMS가 알아서 결정함.

데이터가 많은건 alter 조심할 것.

**DML-데이터 조작어**

INSERT INTO () VALUES ~~

SELECT * ~

UPDATE ~ SET ~ WHERE

DELETE FROM- WHERE

**DCL - 데이터 접근 권한 관리 언어**

1. 기획자도 DB에 접근해서 데이터 보고 싶으면 -> 조회 권한만 부여해서 처리 할 수 있음.
2. DBA, devops 라고 하면 모든 권한을 주거나 하는 식으로 가능함.

정리 :

- DDL, DML, DCL 의 차이
- DDL로 데이터의 구조를 만들고
- DML로 데이터 삽입하고 조회, 수정, 삭제함
- DCL로 데이터 접근을 통제함.

**SQL 응용**

Join 하나 이상의 테이블을 새 테이블 열로 결합하는 것.

User는 회원, product는 상품, purchase는 상품 테이블

Purchase 테이블 안에 user_id와 product_id가 회원과 상품을 연결한다고 가정.

요구 사항으로 -> 1번 유저가 구매한 상품의 이름과 가격이 궁금하다.

1번 유저 정보 -> user, 상품 정보 -> product, 그 연결고리는 purchase 테이블.

JOIN에 대한, INNER, LEFT, RIGHT 조인은 알아야 함.

**View**

가상의 테이블. 쉽게 데이터 저장하는 것이 아니라 쿼리 자체를 저장해두고 쉽게 접근 할 수 있도록 하는 기능

성능을 향상 시켜주는건 아님.

- > 테이블 처럼 보이지만 db에 저장된 쿼리의 별명을 만들어주는거임.
- > 편하게 날쿼리 쓸때의 이점이지 잘 사용되지는 않음.

**Union**

두 SQL쿼리문의 결과를 합치는 연산자 임.

주의 사항으로는 합칠 쿼리의 갯수나 타입 중요함.
