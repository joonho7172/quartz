**비동기 - 프로미스(Promise)**

콜백은 비동기 작업이나 특정 작업 끝났을때 실행해달라고 함수를 넘기는 것.

프로미스는 보이는 코드랑 실제 실행 순서가 다른 대표적인 예시

정의 :

프로미스 객체도 “이 비동기 작업이 당장 결과는 없지만 미래의 결과를 준다”는 약속을 담은 객체

프로미스는 자바 스크립트에서 비동기 연산이 완료된 이후의 결과를 명확하게 처리 할 수 있도록 도와줌

비동기 작업에서는 결과가 왔을 때 성공인지 실패인지 어떻게 아느냐..

- > 이 시점이 프로미스
- > 비동기 작업을 시작 할 때 자바 스크립트가 일단 지금은 바로 돌려주는 결과 보관함 같은 개념
- > 음식 주문 하면 받는 진동벨
- > 프로미스도 똑같이 보관함에 대고 성공해서 결과가 담기면 이걸 해줘 -> then으로 처리

실패해서 이유가 담기면 그걸 catch로 처리

- > 그러면 결과가 도착하는 순간 자바 스크립트가 알아서 코드를 실행해줌

프로미스 객체가 갖고 있는 세가지 상태

Pending -> 보관함이 비어서 결과를 기다리는 중

Fulfilled -> 성공 결과가 담긴 상태

Rejected -> 실패 이유가 담긴 상태

프로미스는 어떤 경우에 쓰냐.

- > 결과가 나중에 도착하는 작업이라면 거의 다 프로미스로 다룸.

사용 이유:

1. 콜백 지옥 해결.
2. 명확한 예외 처리 방식 제공
    1. 성공은 then, 실패는 catch
3. 비동기 작업의 체이닝 용이성
    1. 프로미스를 사용하면 여러 비동기 작업을 연속적으로 연결 가능.
4. 병렬 비동기 작업 처리 기능

Promise 상태

- 대기 pending
    - 프로미스가 생성되어 비동기 처리가 아직 완료되지 않은 상태.
    - 작업이 완료되기 전까지 이 상태.
    - 막 생성돼서 결과를 기다리는 중
- 성공 fulfilled
    - 성공해서 resolve가 호출된 값. resovle = promise의 결과값.
- 실패 rejected
    - 프로미스가 에러 원인을 반환한 상태.
    - 작업 중에 문제가 생겨서 reject 호출된 상태고 에러메시지나 에러 객체가 실패 원인으로 담겨서 처리 됨.

상태는 단 한번만 확정됨.

처음엔 pending 그 후에 rejected, resolve 중 한번.

- > 상태가 바뀌면 절대로 이후에 안바뀜.

**은 여러개의 프로미스를 병렬로 실행하고 모든 프로미스가 성공 했을 때 한번에 결과를 처리 할 수 있게 해주는 방식.**

모든 프로미스가 성공 할 때까지 기다렸다가, 가져오는 것.

결과의 순서는 배열에 넣은 순서 그대로 보장

Promise all에서 병렬로 처리하진 않음

- > 자바 스크립트는 싱글 스레드임
- > 네트워크 요청 같은 일은 브라우저나 서버가 대신 해주는 동안 js는 기다리는 것.
- > 요청해놓고 기다림.(병렬이 아님)

정리

- promiseall로 병렬 처리 가능.

**비동기 - Async / Await**

- > 콜백 지옥에서 프로미스 체이닝으로 코드 평평하게 만들면서 코드 읽기 좋아짐.
- > then도 계속 길어지면 한번 번역을 해야함
- > 지금 배우는 것들은 그것을 더 좋게 만드는 것.

프로미스를 대체하는 게 아니라 프로미스 위에 씌운 문법적 설탕

- > 겉모습만 동기처럼 보이게 해주고 안에서는 여전히 프로미스랑 마이크로 태스크 큐 돌아감.

정의

promise가 완료ㅕ될 때까지 비동기 함수의 실행을 일시 중단하고, 완료된 promise의 결과를 반환하는 키워드

- > 프로미스
- > 프로미스는 결과를 지금 당장은 못주지만 나중에 주겠다 라는 약속을 담은 객체

Async : 함수 앞에 붙이는 키워드 async function 이름 {}

- > 이 순간 부터 “프로미스를 반환하는 함수” 가 됨
- > 핵심은 함수 안에서 우리가 무엇을 return 하든 상관이 없음.

그래서 async가 붙은 함수를 호출한 쪽은 then을 붙여서 결과를 받을 수 있음.

Await : async 함수 안에서 프로미스 안에 붙이는 키워드

- > 문자 그대로 기다리는 것임.
- > 프로미스가 끝날 때까지 기다렸다가 결과값 꺼내서 돌려줌
- > 이 결과를 콜백 없이 그대로 변수에 담을 수 잇음.

콜백 안으로 들어갈 필요 없이 결과가 그냥 변수 num에 넣을 수 있다는 것.

await랑 async는 짝으로 다님

Await 쓰고 싶으면 async 함수 안에서 쓰는게 규칙.

일반 함수에서 쓰면 에러남.

프로미스 쓰고 싶으면 async, 그걸 변수로 값 받고 싶으면 await

사용 이유 : 비동기 작업을 더 직관적이고 동기적인 코드 흐름으로 작성하기 위해서

코드가 promise 의 완료를 기다리는 동안 다른 작업을 차단하지 않으면서 비동기 작업을 처리 하기 위해서

비동기 코드를 위에서 아래로 동기 코드 읽듯이 해주겠다는 것.
