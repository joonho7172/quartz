**자바 스크립트 엔진**

콜백 프로미스, async await는 한번에 하나씩 코드를 실행한다는 전제

그 실행은 누가 어떻게 하는가? 를 볼 차례

- > 그 출발점이 자카 스크립트 엔진

정의 :

자바스크립트 코드를 실행하는 프로그램 또는 인터프리터.

엔진이 파일을 실행하는 방식이나 함수를 실행하는 방식이나 큰 차이가 있진 않음.

- > 먼저 필요한걸 준비 시키고 실제로 실행하는 단계로 공통됨.

사용 이유 :

웹 페이지에 동적 기능을 제공하고 상호작용 하기 위해서

엔진은 어디까지나 JS 코드를 실행하는 부분.

1. 생성과 컴파일 단계 - 코드를 읽고 구조를 파악, 실행할 준비 단계
2. 실행 단계 - 준비된 것을 실행

**생성과 컴파일 단계**

힙 - 크기가 유동적인 데이터 저장 공간 (객체, 배열)

- > 비동기의 이유 (web api나 태스크 큐 같은 것들)

**Execution Context**

엔진 안에서 코드를 쌓아 올려서 처리하는 콜스택, 값 보관하는 힙이 있음.

- > 콜스택위에 뭐가 쌓이느냐?
- > 실행 컨텍스트가 답.

정의:

코드가 실행 될 때 제공할 환경 정보들을 모아둔 객체

함수 하나가 호출되는 순간

- > 그 함수가 돌아가려면 엔진은 여러가지 알고 있어야함.
- > 그 정보들을 하나의 묶음으로 정리
- > 그 묶음이 실행 컨텍스트

실행 컨텍스트는 우리가 코드로 만드는 대상 아님.

사용 이유 :

엔진이 어떻게 코드를 이해했는지 알아 코드에 문제 없게 하기 위해

실행 컨텍스트 쌓이는 방식

1가지 원칙. 새로운 실행 컨텍스트는 함수가 호출 될 때 만들어짐.

- > 코드가 처음 실행 되는 순간 전역 컨텍스트가 가장 먼저 깔림.

모든 코드가 끝나면 전역 컨텍스트까지 사라짐.

콜스택에서는 후입 선출의 의미

코드에서는 호출을 기본이다.

정리:

- 실행 컨텍스트는 코드가 실행될 때 엔진이 필요한 환경 정보를 모아두는 묶음
- 콜스택 위에 쌓였다가 함수가 끝나면 사라짐
- 전역 컨텍스트 먼저, 함수 호출 되 ㄹ때마다 새 컨텍스트 올라감.

**스코프**

함수가 호출 될 때마다 그 함수가 사용할 변수와 환경정보를 모아둔 객체가 있음

- > 그 안에는 바깥 환경을 가리키는 참조 outerEnvironmentReference가 들어있음.
- > 변수 찾을 때 없으면 바깥 참조 따라서 찾아감

정의 :

변수에 접근 할 수 있는 범위

JS에서 스코프는 세가지임.

1. 전역 스코프
    1. 코드의 가장 바깥.
    2. 여기에서 선언된 변수는 프로그램 어디에서나 접근 할 수 있음.
    3. 어디서든 쓸 수 있다고 해서 편해보이지만 어디서든 바뀔 수 있음.
2. 함수 스코프
    1. 함수 하나의 안쪽 범위
    2. 내부에서 선언된 변수는 함수 안에서만 있고 밖에서는 없는 것 처럼 취급됨
3. 블록 스코프
    1. 중괄호로 둘러쌓인 덩어리. if나 for, while 등..
    2. Let const 선언 변수가 블록 스코프
    3. 함수 스코프 보다 좁음

이런 스코프들은 서로 떨어져있는게 아니라 안에서 바깥으로 겹겹이 포개져 있음.

- > 어떤 변수를 사용 할 때 안쪽 스코프 부터 찾고 없으면 바깥..

스코프는 호출 위치가 아니라 작성 위치를 따르는 성질 -> 렉시컬 스코프

사용 이유:

전역에 다 변수를 두지 않는 이유

1. 변수 충돌 방지
2. 규모가 커지면 서로 다른 사람이 짠 코드 , 서로 다른 라이브러리가 충돌 할 수 있음.
3. 메모리 관리

사용 방법

어떤 키워드가 어떤 스코프를 갖는지 정리

var는 함수 스코프나 전역 스코프를 갖고 let, const는 블록 스코프를 가짐.

Var는 함수 안에서 선언하면 함수 스코프, 아니면 전역 스코프

함수 스코프는 함수를 호출 할 때마다 스코프가 매번 새로 만들어짐.

- > 그래서 함수 안에서 선언한 지역 변수는 호출이 끝나고 사라지고 다음엔ㄴ 새롭게 시작함.

전역변수의 문제 - 모두가 쓸 수 있으니 누가 바꿧는지 모름

그리고 이름 충돌의 문제점

정리:

var는 함수 스코프, let, const는 블록 스코프 .. var는 블록 스코프를 갖지 않음.

블록(if 나 for가 있어도 var는 가두지 못함)

스코프 : 변수에 접근 할 수 있는 범위

변수가 어디까지 보이는지 정하는 규칙. 그 범위는 코드를 어디에 작성했는지로 결정됨.

전역, 함수, 블록

변수 사용할 때는 가장 안쪽 스코프부터 바깥으로 올라가면서 찾고 이 경로 스코프 체인

가져가야 할 핵심

- 엔진은 우리가 쓴 코드를 컴퓨터가 실행 할 수 있는 형태로 바꿔서 실행.
- 엔진은 곧바로 돌리지 않고 준비한 다음 실행
- 어떤 변수를 쓸 수 있는지는 어디서 적었는지에 결정 -> 스코프, 호이스팅
- js런타임 환경이 무엇인짖 알아야함.
- 왜 런타임 환경이 필요한지
- 엔진과 런타임 환경의 차이. 런타임 환경이 더 큰 배경
- 환경에 따라 코드에서 쓸 도구가 달라짐. 같은 코드라도 브라우저에서 실행될지 node.js에서 실행될지
- 실행 컨텍스트는 엔진이 코드 실행하려고 만드는 환경 정보 묶음.
- 컨텍스트는 호출될때 생기면 끝나면 사라짐
- 스코프는 변수에 접근 할 수 있는 범위. 그 범위는 변수를 어디에 작성 했는지 정해짐. 호출위치가 아니라 작성 위치
- 스코프는 전역, 블록, 함수로 나뉘도 안에서 바깥으로 포개진 구조
- 변수 사용 할 때 엔진은 가장 안쪽 스코프부터 바깥으로 올라가면서 찾음. - 스코프 체인
