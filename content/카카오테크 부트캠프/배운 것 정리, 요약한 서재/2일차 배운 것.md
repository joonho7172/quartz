초반 복습 : jdk 만 다운받지 않고 jre만 받아서 설치 하는데 도움

JVM은 그저 바이트코드를 실행하는 가상의 머신일뿐 이라고 이해하자

바이트 코드 -> JVM이 실행하기 위한 형태의 코드, 사람이 읽기 쉽지 않음 실제 운영체제가 직접 실행 할 수가 없는 코드임

왜? WHY? -> 운영체제 독립성임 다른 운영체제에서도 실행되기 위해서 바이트 코드로 변환 후 JVM에서 실행하는거임 (근데 그렇다고 너무 막 쓰진 못한다)

JVM의 동작방식

- 개발자가 .java 파일 작성
- 파일을 컴파일 해서 .class 파일 만듦 -> 바이트 코드
- .class 파일을 클래스 로더 라는 것을 통해서 읽어 들임 (여기서부터 jvm의 역할 시작임)
- 로딩된 클래스를 검증, 준비, 해결, 초기화 하는 과정을 거침
- 그리고 JVM의 런타임 데이터 영역( 메모리 영역 )에 필요한 정보들이 배치가 됨
- 그리고 실행 엔진이 바이트코드를 interpreting하거나 필요하면 jit compile 하면서 실행함

**클래스 로딩**

JVM의 클래스 로더 -> 바이트 코드 클래스를 JVM의 메모리 영역에 올림

시작하자마자 모든 클래스를 한번에 올리지 않고 실제로 필요한 시점에 동적으로 로딩함 -> 지연 로딩임

# 여러개의 클래스를 시작 시점에 다 가져오는게 아니라 필요 시점에 가져오는거임 #

클래스 로더의 순서는 이러함

- Loading -> Linking -> Initializing

**런타임 데이터 영역**

JVM은 프로그램 실행 중에 필요한 데이터를 여러 영역으로 나누어서 관리함

기본적으로는 힙 영역과, 메소드 영역, 다른 스레드 영역. 3가지인듯?

일부는 시작할때 만들어지고 일부는 실행 중에 만들어지는 영역이 있음

즉, 데이터 마다의 생명주기에 따라서 영역을 나누어서 사용을 하는 것임

메소드랑 힙 영역은 공유함..

즉, 공유하거나 공유하지 않는 영역들이 있음.

**1. 힙 영역**

객체와 배열이 저장되는 공간임

young generation 	구간과 old generation 이 나뉘어져 있음

예시로는 new String[10] 하면 힙에 10칸짜리 배열 객체가 생기는거

만약에 힙 영역이 가득차게 되면 GC가 나서서 정리를 해주는 것임

**스택 영역**

메소드 작업 공간임

메소드가 하나씩 쌓일 때마다 스택 공간에 작업대가 생기는데 이게 바	로 “스텍 프레임” 이다.

물론 메소드가 종료되면 해당 스텍 프레임은 사라짐

예시를 들면

Car car =new Car() 라는 것에서 실체 객체는 힙, 참조 변수는 메모리 주소를 안에 넣음

**PC register**

그냥 스레드별 실행 위치를 표시하는거임

명령어를 한줄 실행하고, 다음 명령어로 이동하고.. 조건문이면 다른 위	치, 반복문이면 제자리.

-이러한 실행 흐름을 추적하려면 현재 어디에서 실행중인지 알아야함-

**실행 엔진**

코드를 바이트코드로 바꾸고 클래스 로더가 이제 각각의 영역에 올린

후에 대한 이야기

이제 메모리에 올렸으니 실행을 해보자는거임.

만능은 아니기 때문에 다른 것들도 고려를 해야함

인터프리터 언어와 컴파일 언어의 차이점이 뭐예요?

<aside> 👨‍💻

컴파일 언어는 코드를 한 번에 기계어로 변환(컴파일)한 후 실행하며, 실행 속도가 빠르고 오류는 사전에 잡히는 경우가 많습니다.

대표적으로 C, C++이 이에 해당합니다.

반면 인터프리터 언어는 코드를 한 줄씩 해석하며 즉시 실행하므로, 실행은 느릴 수 있지만 수정과 테스트가 빠릅니다.

JavaScript나 Python이 여기에 속합니다.

자바는 이 둘의 장점을 결합해, 먼저 바이트코드로 컴파일한 뒤, JVM이 이를 해석하거나 JIT 컴파일로 실행합니다.
