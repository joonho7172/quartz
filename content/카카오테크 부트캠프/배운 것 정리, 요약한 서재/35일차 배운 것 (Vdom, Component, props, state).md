**VDOM**

중요한..

VDOM이 무엇인지., 왜 리액트가 쓰는지, 화면 바뀔 때 어떤 순서, 규칙으로 업데이트 하는지 -> vdom은 리액트가 화면이 어떤 모습이어야 하는지 메모리 안에 가벼운 js로 표현해두고 바뀌기 전 후를 비교해서 달라진 부분만 화면에 반영..

가져가야 할 핵심

- VDOM은 실제 DOM을 복사본 같은 역할 + 리액트 화면의 가벼운 설계도
- 화면이 바뀔 때 리액트가 렌더링 한다는 것은. 화면을 다시 그리는게 아닌, 데이터로 다시 계산한다는 뜻. 설계도를 새로 그린다 ㅇㅇ
- 리액트는 달라진 부분만 화면에 반영.

정의 :

실제로 DOM을 조작하지 않고, 변경 사항을 메모리 상의 가상구조에서 먼저 처리하는 기술.

DOM : 브라우저는 HTML 문서를 읽으면 화면에 포현 될 수 있도록 그 내용을 투리구조로 바꿔서 표현, 트리구조를 DOM

VDOM : 화면이 바뀔 때 실제 DOM을 건들지 않고 그 변경 사항만 메모리 상의 가상 구조에서 처리하는 것.

DOM이 실제 집이면 VDOM은 그 집의 설계도.

수정 사항이 있으면 새로 설계도(VDOM)를 그려보고 원래 DOM과 비교해서 필요한 부분만 수정할 수 있게 해줌

- > 데이터 하나 바뀌었을때, 화면의 어느 돔을 바꿔야 하는지 기억하고 관리해야하는 불편함을 해소 하기 위함.
- > 실수가 생기기 쉬운 것도 해소 가능.

리액트는 이 문제를 풀어나감.

- > 개발자가 돔을 직접 찾아가면서 수정하기 보다 현재 데이터를 기준으로 화면이 어떤 모습이어야 하는지를 JSX로 선언
- > 예를 들어 liked가 true면 버튼은 활성화된 모양, stock이 0이면 품절.. 등등

그러면 리액트는 그 JSX를 실행하면 지금 화면이 어떤 구조여야 하는지를 JS 객체 트리로 계산.

그 메모리 안의 화면 구조 표현이 VDOM이다.

(실제 화면 만들기 전에 리액트가 메모리 안에 그려두는 화면 설계도)

DOM - 브라우저가 HTML 문서 해석해서 만든 트리구조, JS로 수정 가능.

- 실제 DOM을 수정하면 화면 그리기를 다시 계산 해야함.
- 렌더링 시스템과 연결된 무거운 객체.
- 반대로 VDOM은 브라우저가 직접 관리하는 화면 객체가 아님.

VDOM - 메모리 안에 있는 JS객체 구조, 화면에 보이지도 않고 사용자가 클릭 할 수도 없고 브라우저가 계산하는 대상

- 리액트가 이전 화면 구조랑 새로운 화면 구조 비교하기 위해서 사용하는 중간 트리

리액트가 화면 이전 상태와 다음 상태를 비교해서 실제 돔에 반영할 최소 변경을 계산.

- 개발자가 직접 명령하는 대신 선언.
- 실제 돔 변경으로 바꾸는 책임은 리액트가.

상태가 바뀜 -> 새로운 VDOM을 만든다. -> 이전 VDOM과 비교해 달라진 부분만 적용함. (Reconciliation)이라고 합니다.

사용 이유

실제 DOM 조작을 최소화해 렌더링 성능을 향상 시키기 이해서 + 개발 방식의 관점 (실제 DOM의 브라우저 렌더링 과정에 직접 연결되어 있음 .. 스타일 리페인트에 어떤 영향을 주는지 알아야 함.

모든 돔을 매번 다시 만드는게 아니라 필요한 변경만 골라서 반영

개발 방식의 관점 - 돔을 직접 개발자가 다루면 어떤 요소를 찾아서 어떤 순서로 수정해야할지 직접 관리해야 한다. -> 개발자가 최종 UI 상태에만 집중 할 수 있게 도와준다. 원래 개발자가 할 일은 DOM 수정 절차나 이게 어디에 있는지 기억하는게 아님.

**STATE**

어떤 컴포넌트가 스스로 소유하고 기억하면서 필요할 때 변경을 요청 할 수 있는 값.

설명 할 수 있어야하는 것

state무엇이 필요한지,react 화면을 어떤 흐름으로 다시 계산하는지.

State의 정의 쇼핑물 화면 - 상품마다 수량 조절 버튼,

수량이 바뀌면 금액도 바뀌는 등.. 쿠폰 도 포함.

사용자의 행동이나 시간의 흐름에 따라 값이 계속 바뀜.리액트에서 state는 이런 값을 관리하기 위함.

정의 : 컴포넌트가 스스로 기억하고 관리하는 값.

- > 렌더링 여러번 일어나도 가밧을

반면 state는 특정 컴포넌트가 소유하는 값. Setter 함수를 통해 state 변경함.

props와 state의 기준은? - 어떤 값은 자식 컴포넌트의 state였다가 여러 컴포넌트가 함꼐 써야해서 부모로 끌어올려질 수 있다.

부모에게는ㅡstate가, 자식은 props

예시로 버튼 색깔 같은건 props로 넘기는 부모가정해주는 값, 몇번 눌렀는지는 사용자의 클릭에 따라서 계속 바뀌는 값..

이 값을 컴포넌트가 직접 기억하고 바꿔야 한다면 state

setCount는 일반 변수에 값을 대입하는게 아니라 다음 화면을 계산 할 때 이 값으로 계산해달라는 요청.

- 요청 받은 리액트는 컴포넌트 함수 다시 실행, 새 counter 기준으로 jsx 다시 계산

state는 단순한 변수가 아닌, state는 렌더링 사이에 리액트가 기억해주는 값이고 setter를 통해 변경을 요청하면 그 값을 바꿔줌

사용 이유

변하는 화면을 만들려면 변하는 값을 어딘가에는 담아두고 관리 해야함.

- > 담아 두고 관리하는 그릇이 state

시간에 따라 변하는 값을 관리하기 위해서 . 버튼 눌러서 숫자 변경, 입력창에 글자 치면 실시간 반영, 서버에서 데이터 받아오는 동안 로딩 상태 등.
