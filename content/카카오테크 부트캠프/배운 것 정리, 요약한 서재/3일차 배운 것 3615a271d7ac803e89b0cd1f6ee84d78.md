**다형성**

- 최종 목표 : 다형성은 “상위 타입하나로 여러 구현 객체를 다루고 실행 시점에 각 객체의 동작이 달리지는 구조”
- 다형성의 실무 가치는 조건문을 줄이고 기능 추가시 기존 코드 수정을 줄일 수 있다.
- 오버로딩은 컴파일 타임, 다형성
- 오버라이딩은 런타임 다형성과 연결되어 있음.
- 실무에서는 인터페이스와 오버라이딩 기반의 다형성이 중요함.

**정적 다형성 (오버 로딩)**

메소드 이름은 같지만 매개변수의 형태나 개수를 다르게 정의하는 것임

컴파일러가 어떤 메소드를 부를지 컴파일 시점에서 선정함

ex) println : 만약 오버로딩이 없으면 printInteger, printString등 	이름이 다 달라야 한다..

**동적 다형성 (오버 라이딩)**

실제 객체가 무엇인지에 따라 런타임에 실행 메소드가 결정된다.

왜??))  코드수정을 최소화하면서 다양한 기능을 유연하게 확장 할 수 있기 때문임.

**상속**

- 최종 목표 : 상속은 자식 클래스가 부모 클래스의 필드와 메소드를 물려받아 재사용하거나 확장하는 구조
- 상속은 중복제거보다 훨씬 더 중요하게 클래스 사이의 관계를 표현하는 도구임
- 단일 상속만 가능, 다단계 상속도 가능
- 실무에서는 인터페이스랑 균형있게 사용

대체적으로 기능은

1. 물려받는다
    1. 부모클래스에서의 변수나 메소드를 자식이 사용한다
2. 재사용한다.
    1. 재사용해서 같은 코드 여러번 ㄴㄴ
3. 확장한다
    1. 부모에게 없는 필드나 메소드를 새로 추가할 수 있음
    2. 예시로는 버스 는 자동차의 부모를 가지지만 뭐 버스 요금이라던지 이런 고유 기능을 따로 가짐

사실 상속은 최종적으로는 코드 재사용 목적보다는 관계를 표현하는 도구라는거임
