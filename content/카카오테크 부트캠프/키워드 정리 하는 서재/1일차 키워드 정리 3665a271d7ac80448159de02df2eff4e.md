# 1일차 키워드 정리

(필수) 인터페이스가 무엇인지 설명하고, 클래스의 구현 세부사항과 인터페이스의 역할이 왜 분리되어야 하는지 설명해주세요.

- 인터페이스는 일종의 계약이다. 클래스의 구현 세부사항에 대해서는 알필요 없고 그것을 “한다.”라는 것만 알면 되기 때문에. 즉, 서로 독립적으로 변경하기 위해서.

인터페이스 타입으로 객체를 참조하면 구현체를 직접 사용하는 것보다 어떤 점에서 유지보수와 확장에 유리한지 예시를 들어 설명해주세요.

- 인터페이스 타입으로 객체를 참조하면 구현체가 바뀌거나 새로 추가가 되어도 사용하는 쪽 코드를 직접 수정할 필요가 없어 용이하다

하나의 클래스가 여러 인터페이스를 구현할 수 있다는 점이 자바 설계에서 어떤 문제를 해결해주는지 설명해주세요.

- 클래스 다중 상속의 충돌은 피하면서 여러 역할을 동시에 부여할 수 있는 유연성은 늘리기 위해서 이다.

캡슐화가 무엇인지 설명하고, 필드를 private으로 감춘 뒤 getter/setter를 제공하는 방식이 왜 객체의 안정성을 높이는지 설명해주세요.

- 캡슐화는 내부의 필드를 클래스가 자체적으로 책임을 지게 하기 위해서이다. private로 필드를 감싸면 외부에서 이 값들을 함부로 변경할 수 없고 getter와 setter를 통해서 한정적으로 변경을 허락하기 때문에 안정성이 높아진다.

getter/setter를 만들었다고 해서 항상 캡슐화가 잘 되었다고 볼 수 없는 이유를 설명하고, setter 내부 검증 로직이 필요한 상황을 예시로 설명해주세요.

- setter가 너무 많이 사용되면 캡슐화의 의미가 약해진다. 내부 검증 로직을 통해 잘못된 값이 들어왔을때 보호 할 수 있다.

public, private, protected, default 접근 제어자의 차이를 설명하고, 각각 어떤 설계 의도를 표현할 때 사용하는지 설명해주세요.

- public은 모두가 사용 할 수 있는 공유자원이고
- private는 클래스 내에서만 변경 할 수 있는 자원(숨겨야함)
- protected는 부모가 자식한테만 허용하는 자원
- default는 같은 패키지 안에서의 공유

제네릭을 사용하는 이유를 Object 타입을 사용하는 방식과 비교해서 설명하고, 제네릭이 ClassCastException을 줄이는 데 어떻게 도움이 되는지 설명해주세요.

- 제너릭은 래퍼 타입을 정해지지 않은 상태로 매개변수로 받고

`List<String>`을 `List<Object>`에 대입할 수 없는 이유를 제네릭의 타입 안정성과 불공변성 관점에서 설명해주세요.

와일드카드 `?`, `? extends T`, `? super T`의 차이를 설명하고, 각각 어떤 상황에서 사용하는 것이 적절한지 설명해주세요.

`? extends T`는 읽기에 유리하고 `? super T`는 쓰기에 유리하다고 말하는 이유를 예시와 함께 설명해주세요.

List, Set, Map의 차이를 데이터 저장 방식, 중복 허용 여부, 접근 방식 관점에서 비교해서 설명해주세요.

ArrayList와 LinkedList의 내부 구조 차이를 설명하고, 조회가 많은 상황과 삽입/삭제가 많은 상황에서 어떤 구현체를 선택해야 하는지 설명해주세요.

Set이 중복을 허용하지 않는 원리를 equals()와 hashCode() 관점에서 설명하고, 둘 중 하나만 오버라이딩했을 때 발생할 수 있는 문제를 설명해주세요.

HashMap에서 key가 중복되면 어떤 일이 발생하는지 설명하고, value는 중복될 수 있는 이유를 설명해주세요.

HashMap, LinkedHashMap, TreeMap의 차이를 순서 유지, 정렬, 검색 성능 관점에서 비교하고, 실무에서 각각 어떤 상황에 사용할 수 있는지 설명해주세요.

HashMap에서 해시 충돌이 발생하는 이유와 충돌이 발생했을 때 값을 찾는 과정을 hashCode(), 버킷, equals() 관점에서 설명해주세요.

(필수) Thread의 start()와 run() 메서드의 차이를 설명하고, run()을 직접 호출하면 왜 새로운 스레드가 생성되지 않는지 설명해주세요.

- run()함수는 이미 클래스에 선언된 메소드를 실행하는 것이고 start()는 메모리에서 콜스택을 받아 새로운 스레드를 만들고 그 곳에 처음으로 run()을 실행시키는 것이다. 기존 스레드냐, 새로운 스레드냐에 대한 차이.

Thread 클래스를 상속하는 방식과 Runnable 인터페이스를 구현하는 방식의 차이를 설명하고, 실무에서 Runnable 방식이 더 자주 사용되는 이유를 설명해주세요.

sleep(), join(), interrupt()의 역할을 각각 설명하고, 스레드 실행 순서 제어와 중단 요청 관점에서 어떻게 다르게 사용되는지 설명해주세요.

스레드 내부에서 예외가 발생했을 때 메인 스레드로 자동 전파되지 않는 이유를 설명하고, 실무에서 이를 어떻게 감지하고 처리할 수 있는지 설명해주세요.
