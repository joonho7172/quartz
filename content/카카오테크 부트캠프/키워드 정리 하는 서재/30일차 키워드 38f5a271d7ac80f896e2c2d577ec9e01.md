# 30일차 키워드

spring security란?

인증과 인가를 포함한 보안 영역을 다루는 spring 하위 모델

인증과 인가란..?

인증은 사용자가 맞는지 확인하는 절차(로그인 등) 인가는 인증된 사용자에 한해 권한 여부를 따지는 것.

HTTP의 stateless와 보안의 연관점?

http는 무상태성 때문에 사용자의 정보를 기억하지 않는다. 요청이 들어오면 확인하기 때문에 그때 마다 이 사용자가 허가된 사용자인지, 인가된 사용자인지 확인해야함.

Spring security는 왜 servlet filter를 사용 할 까?

→ controller에 닿기 전에 처리하기 위해서..

filter와 Interceptor의 차이점이 있을까?

작동 시점의 차이가 있음. filter같은 경우에는 controller에 닿기 전에 작동 하는 것.

filter 같은경우는 servlet 단계에서 작동하고, dispatcher servlet에 가기 전에 작동을 함. 즉, 어떤 controller인지 모르고 작동한다는 점. 그 때문에 전역 보안에 사용 가능.

interceptor는 dispatcher에게 어떤 controller에게 갈지 요청을 받은 다음에 가로채기 때문에 전역적인 보안을 하기에는 무리가 있음.

DelegatingFilterProxy가 하는 일 , 이유?

DelegatingFilterProxy는 servlet 단계의 필터에서 의존성 주입이나, bean 객체를 사용하지 못하기 때문에 spring 단계의 security filter로 내려보내는 역할을 한다.

즉, servlet container에 있는 필터를 지나 spring bean으로 관리되는 필터들로 연결 시켜주는 것이 delegatingFitlerProxy이다,

FIlterChainProxy가 하는 동작이란?

filterchain은 여러가지 springfilter의 묶음으로 보낸 요청에 따라 알맞는 security이 검사 조건으로 보내 주는 역할을 한다.

securityContextHolder 는 어떻게 동작하고 어떤 역할?

인증이 완료된 요청은 Authentication이라는 객체에 들어가게 되는데 그것들을 담아 놓은게 security Context, 그리고 그것들의 집합이 securityContextHolder이다. threadLocal을 통해 여러 스레드들이 사용자의 정보에 접근 할 수 있게 해줌.
