# 한줄 정리

registry

컨테이너의 이미지는 빌드한 컴퓨터의 로컬에만 존재함. 아무리 dockerfile이 있어서 이미지를 만들 수 있다 해도, 실행 서버로 옮겨가지는 않음.

→ 중앙에서 컨테이너 이미지를 저장하고 배포하는 이미지 전용 저장소가 registry

배포 일관성이랑 자동화에 유리하고, 이미지 태그를 이용해서 버전을 구분하기에 롤백에도 유리하다. 

ECR - aws에서 제공하는 완전 관리형 컨테이너 이미지 registry이고,

aws환경에서는 iam, region, aws 컨테이너 서비스와 통합된다는 차이가 있다.

volume은

컨테이너가 삭제되면 쓰기 레이어도 함께 삭제되기 때문에 컨테이너 내부에 저장한 데이터도 사라진다.

이러한 컨테이너의 생명 주기와 데이터의 생명 주기를 분리하기 위함.

컨테이너와 volume을 연결하는 작업 - 마운트, 하나의 volume을 여러개의 컨테이너와 연결 가능하다..(공유 테이터)

Bridge Network 

동일한 Docker Host안에 있는 여러 컨테이너를 하나의 가상 내부방으로 연결하는 Docker 네트워크 방식.

간단하게 말하면 컨테이너들의 통신 수단.

bridge network에서는 docker의 내부 dns를 사용할 수 있으므로 컨테이너의 ip대신 이름을 사용 할 수도 있다.

docker compose

여러 컨테이너의 실행구조를 yaml 파일에 선언하고 관리하는 것.

실행은 docker engine이 한다.

- 얘가 하는 일은 컨테이너를 실행할때마다 이미지, 포트, volume등을 명령어로 직접 지정할 필요가 없음.
