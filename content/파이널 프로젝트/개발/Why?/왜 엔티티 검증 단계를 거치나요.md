엔티티 검증은 최후의 방어선이다...
나는 왜 엔티티 단에서 검증을 해야하는지 이해를 못했다. 

엔티티에는 필드명 적혀져 있고, 
마지막에
```java
private static void validateCreate(String email, String name){
    Assert.hasText(email, "email required");
    Assert.hasText(name, "name required");
}
```

그냥 단순하게 email이랑 name 필드가 채워져있는지 확인하는 검증 단계이다. 
근데 어차피 Service에서 비즈니스 로직 오류를 잡고, Controller에서 @NotNull, @NotBlanck를 통해서 validation 검증을 하고, entity에서 필수값 검증과, length 를 통해서 길이 검증도 하는데, 

이렇게 엔티티 검증 단계는 과하지 않을까 하는 생각이 들었다.

이러한 엔티티 검증의 단계는 만약을 위한 안전 장치로, 

주의해야 할 점은 **커스텀 예외**([[CustomException]])가 아닌, **순수 예외***([[IllegalArgumentException]], [[IllegalStateException]])로 잡아야 한다는 것이다. 

그 이유는 
1. 책임 소재 명확화
	1. 엔티티 검증이 뚫렸다는 것은 어딘가에서 개발자의 실수가 있었다는 뜻.
	2. ```java
	   throw new. IllegalArgumentException("email required"); //와 같은 오류는안됨.
	   ```

2. 도메인의 책임 순수성
	1. ```java
	   
	   throw new EmailTooLongException(); //와 같은 커스텀 예외 클래스에 의존하게 된다.
	   throw new IllegalArgumentException("email too long"); 과 같이 의존성이 없어진다.
	   ```
	   
2. 예외 처리 전략 구분
    
    - **비즈니스 예외**(CustomException): 사용자에게 친절한 메시지 반환
    - **검증 예외**(IllegalArgumentException): 500 에러로 로깅하고 개발자가 수정
