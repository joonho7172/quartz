### 회원가입/ 로그인 API

- **API 명세:**
    
    - `POST /api/auth/oauth`
    - API 문서 링크: [API Docs 링크 - 회원가입]
- **권한:**
    - 비로그인 사용자 허용 (`PermitAll`)

- **Request Header:**
    

```
Content-Type: application/json
Accept: application/json
```

- **Request Body:**

```
{
  "provider": "KAKAO",
  "authorizationCode": "카카오에서 전달받은 인가 코드"
}
```

- **구현 상세:**

	* 요청 (Request Body) : 기업으로 부터 제공받은 사용자의 인가코드, 회원가입 정보를 제공한 기업의 이름과 state 
		* 서버가 예측할 수 없는 일회성 state (SecureRandom)으로 값을 생성하고 서버 callback의 URL에 Query parameter로 넣습니다.
		* 일회성 state이므로, redis에 저장 후 ttl을 5분으로 잡습니다. 브라우저 세션 ID와 provider를 함게 저장합니다
		* 서버가 로그인 요청 URL에 state를 포함하고, callback URL의 state를 비교해 검증합니다.
	    
    1. `provider`와 `authorizationCode`의 유효성을 검증함.
    2. 카카오 OAuth API에 인가 코드를 전달해 카카오 Access Token을 발급받습니다.
    3. 서버가 받은 카카오 Access Token으로, 카카오 사용자 정보 API를 호출해 `provider_user_Id`, 닉네임, 프로필 이미지를 가져옵니다. (프론트 응답으로 하지 않고 서버에서 처리)
    4. `provider`와 `providerId`로 기존 회원을 조회합니다.
    5. 기존 회원이 없으면 `users` 테이블에 회원 정보를 저장합니다.
    6. 서비스용 Access Token을 발급합니다. (카카오 Access Token이 아닌, 우리 서버 API 호출을 위한 Access Token)
    7. Refresh Token은 HttpOnly 쿠키로 발급하고, 서버에는 만료 시간·폐기 시간 등 토큰 정보를 저장합니다. (Refresh Token은 body에 넣지 않고 Httponly, secure, samsite 옵션이 적용된 쿠키)
	    1. 카카오 로그인을 위한 Access Token을 위한 Refresh token이 아닌 우리 서비스만의 refresh 토큰.
    8. 동일한 카카오 계정으로 동시에 가입 요청이 들어오는 경우 `provider`와 `providerId`에 Unique 제약조건을 적용해 중복 회원 생성을 방지합니다.
    9. 회원가입이 완료되면, 신규 회원 여부를 true로 처리하고, 기존 회원 이면 false로 처리한다.

-  **트랜잭션 및 외부 API 처리:**
  - `authorizationCode` 검증과 카카오 OAuth API 호출은 DB 트랜잭션 외부에서 처리합니다.
  - 카카오 API 호출이 끝난 뒤, 우리 서비스의 회원 조회·회원 생성·Refresh Token 저장 또는 갱신을 하나의 트랜잭션으로 처리합니다.
  - 회원 생성 또는 Refresh Token 저장에 실패하면 전체 트랜잭션을 롤백합니다.
  - 트랜잭션이 성공적으로 커밋된 후에만 Access Token 응답과 Refresh Token 쿠키를 반환합니다.
  - 동시에 동일한 카카오 계정으로 요청이 들어오는 경우 `oauth_provider`, `oauth_provider_id`의 Unique 제약조건으로 중복 회원 생성을 방지합니다.
  - 중복 키 오류가 발생하면 기존 회원을 다시 조회하여 로그인 처리할 수 있습니다.


- **Response:**
    
    - 신규 회원가입: `201 Created`
    - 기존 회원 로그인: `200 OK`
    - 신규 회원 여부는 DB 컬럼이 아니라 응답용 `isNewUser` 값으로 판단합니다.

```
{
  "data": {
    "accessToken": "우리 서비스 Access Token",
    "tokenType": "Bearer",
    "expiresIn": 1800,
    "isNewUser": true,
    "user": {
      "userId": 101,
      "nickname": "닉네임",
      "profileImageUrl": "https://example.com/profile.png"
    }
  },
  "error": null
}
```

응답 헤더:

```
Set-Cookie: refresh_token={refreshToken}; HttpOnly; Secure; SameSite=Lax; Path=/api/auth; Max-Age=1209600
```

- **주요 오류 코드:**
    
    - `400 BAD_REQUEST`: 인가 코드 형식 오류
    - `401 UNAUTHORIZED`: 카카오 인증 실패 또는 인가 코드 만료
    - `409 SOCIAL_ACCOUNT_CONFLICT`: 이미 다른 회원과 연결된 카카오 계정
    - `500 INTERNAL_SERVER_ERROR`: 회원가입 처리 중 서버 오류

## 로그아웃 API

- **API 명세:**
    
    - `POST /api/auth/logout`
    - API 문서 링크: [API Docs 링크 - 로그아웃]
- **권한:**
    
    - Refresh Token 쿠키를 보유한 사용자
    - Access Token이 만료된 상태에서도 로그아웃할 수 있도록 `PermitAll`로 처리할 수 있습니다.
- **Request Header:**

```
Accept: application/json
Cookie: refresh_token={refreshToken}
```

`Content-Type`은 Request Body가 없으므로 사용하지 않습니다.

- **Request Body:**

```
없음
```

- **구현 상세:**
    
    1. 요청 Cookie에서 `refresh_token`을 가져옵니다.
    2. Refresh Token을 해시하여 DB에서 조회합니다.
    3. 유효한 토큰이면 `revokedAt`을 기록하여 폐기합니다.
    4. 동일 사용자의 현재 세션만 로그아웃하거나, 정책에 따라 모든 Refresh Token을 폐기합니다.
    5. 응답에서 Refresh Token 쿠키를 삭제합니다.
    6. Access Token은 JWT인 경우 즉시 폐기하지 않고 만료될 때까지 유효할 수 있으므로, 필요하다면 Redis에 블랙리스트를 저장합니다.
- **Response:**
    

```
204 No Content
```

```
Response Body: 없음
```

- **Response Header:**

```
Set-Cookie: refresh_token=;
              Max-Age=0;
              Expires=Thu, 01 Jan 1970 00:00:00 GMT;
              HttpOnly;
              Secure;
              SameSite=Lax;
              Path=/api/auth
```

- **주요 오류 코드:**
    
    - Refresh Token이 없거나 이미 폐기된 경우에도 로그아웃은 성공한 것으로 처리할 수 있습니다.
    - `500 INTERNAL_SERVER_ERROR`: 로그아웃 처리 중 서버 오류

로그아웃은 여러 번 요청해도 결과가 같도록 만드는 것이 좋으므로, 이미 로그아웃된 상태에서도 `204 No Content`를 반환하는 방식이 적절합니다.

## 회원 탈퇴 API

- **API 명세:**
    
    - `DELETE /api/users/me`
    - API 문서 링크: [API Docs 링크 - 회원 탈퇴]
- **권한:**
    
    - 로그인한 사용자 (`IsAuthenticatedUser`)
- **Request Header:**
    

```
Authorization: Bearer {accessToken}
Accept: application/json
Cookie: refresh_token={refreshToken}
```

Request Body가 없으므로 `Content-Type`은 사용하지 않습니다.

- **Request Body:**

```
없음
```

- **구현 상세:**
    
    1. Access Token을 검증하여 탈퇴 요청 사용자를 확인합니다.
    2. 해당 사용자의 활성 Refresh Token을 모두 폐기합니다.
    3. `users` 테이블의 회원 상태를 탈퇴 상태로 변경합니다.
    4. 서비스 데이터의 참조 관계를 고려하여 회원 정보는 Soft Delete 또는 익명화 처리합니다.
    5. 회원 탈퇴 후에는 해당 카카오 계정으로 다시 로그인했을 때의 처리 정책을 확인합니다.
        - 재가입 불가: 탈퇴 회원으로 판단하여 로그인 거부
        - 재가입 허용: 기존 회원을 복구하거나 새 회원으로 처리
    6. 카카오 앱과의 연결 해제가 필요하다면 카카오 연결 해제 API를 호출합니다.
    7. 카카오 API 호출은 DB 트랜잭션 외부에서 처리하고, 우리 DB의 회원 상태 변경과 Refresh Token 폐기는 하나의 트랜잭션으로 처리합니다.
    8. 응답에서 Refresh Token 쿠키를 삭제합니다.
- **트랜잭션 처리:**
    
    - 회원 상태 변경과 Refresh Token 폐기는 하나의 트랜잭션으로 처리합니다.
    - DB 처리에 실패하면 회원 상태와 토큰 폐기 작업을 모두 롤백합니다.
    - 카카오 연결 해제 API를 동기 호출한다면 해당 API 실패 시 탈퇴를 중단하거나 재시도 대상으로 저장해야 합니다.
    - 트랜잭션이 성공적으로 완료된 후에만 쿠키 삭제 응답을 반환합니다.
- **Response:**
    

```
204 No Content
```

```
Response Body: 없음
```

- **Response Header:**

```
Set-Cookie: refresh_token=;
              Max-Age=0;
              Expires=Thu, 01 Jan 1970 00:00:00 GMT;
              HttpOnly;
              Secure;
              SameSite=Lax;
              Path=/api/auth
```

- **주요 오류 코드:**
    
    - `401 UNAUTHORIZED`: Access Token이 없거나 유효하지 않음
    - `404 USER_NOT_FOUND`: 탈퇴 대상 회원을 찾을 수 없음
    - `409 ACCOUNT_WITHDRAWAL_CONFLICT`: 현재 상태에서 탈퇴할 수 없음
    - `502 KAKAO_UNLINK_FAILED`: 카카오 연결 해제 요청 실패
    - `500 INTERNAL_SERVER_ERROR`: 회원 탈퇴 처리 중 서버 오류

- **성능:**
    - 외부 카카오 API를 연동하므로 전체 로그인 응답 시간은 1초 이하로 목표를 설정합니다.
    - DB에서 provider와 provider_user_id에 복합 UNIQUE 인덱스를 설정하여 조회 속도를 높입니다.
    - 동시 로그인 요청과 회원가입 요청에 대한 부하 테스트를 진행 합니다.

- **카카오 OAuth 안정성:** 
	- 카카오 토큰 api와 사용자 정보 api에 연결 타임 아웃을 설정합니다. 
	- 인가 코드는 일회성 토큰이므로 토큰 발급 API를 반복해서 호출하지 않도록 합니다.
	- 카카오 API 호출은 외부 트랜잭션으로 처리하고, 실패 시 회원 생성 트랜잭션을 시작하지 않습니다.

- **데이터 정합성:**
	- 카카오가 보낸 사용자 고유의 id를 provider_user_id로 저장합니다.
	- provider와 provider_user_id를 복합 UNIQUE로 설정해 중복해서 가입되지 않게 합니다.
	- 동시에 같은 요청이 들어오면 UNIQUE 제약조건 처리하고 기존 회원을 돌려보냅니다.
    - DB 트랜잭션이 성공해야만 사용자의 access token과 refresh token 쿠키를 반환 합니다.

- **보안:**
	- refresh token은 원문을 저장하지 않고 hash값을 DB에 저장합니다.
	- `authorizationCode`는 서버에서만 카카오 토큰 API에 전달하고, 클라이언트가 보낸 `providerId`, 닉네임, 프로필 이미지는 신뢰하지 않습니다.
	- 탈퇴나 로그아웃 시, 사용자의 refresh token을 만료, 폐기 합니다.
