# **배경 (Background)**

- **프로젝트 목표 (Objective):** 사용자에게 더 빠르고 안정적인 주문 경험을 제공하여 구매 전환율을 높이고, 운영 효율성을 개선한다.
    - **핵심 결과 (Key Result) 1:** 3분기 내 주문 완료까지 평균 소요 시간 15% 단축 (현재 대비)
    - **핵심 결과 (Key Result) 2:** 3분기 내 주문 관련 고객 문의(CS) 10% 감소 (현재 대비)
    - **핵심 결과 (Key Result) 3:** 신규 결제 수단(OO페이) 도입 후, 해당 결제 수단 이용률 5% 달성
- **문제 정의 (Problem):**
    - 현재 주문 프로세스는 여러 단계를 거쳐야 해서 사용자가 중간에 이탈하는 경우가 많습니다. (데이터: 장바구니 → 주문 완료 전환율 X%)
    - 특정 시간대(예: 이벤트 진행 시)에 주문량이 몰리면 시스템 응답 속도가 느려져 사용자 경험을 저해하고, 때로는 주문 실패로 이어집니다.
    - 최근 사용자들이 선호하는 간편 결제 수단(OO페이)이 지원되지 않아 결제 단계에서 이탈하는 사용자가 있습니다. (사용자 서베이 결과)
- **가설 (Hypothesis):** 주문 단계를 간소화하고, 시스템 성능을 개선하며, 인기 있는 결제 수단을 추가하면 사용자의 주문 경험이 향상되어 구매 전환율이 높아지고 운영 부담도 줄어들 것이다.

### **주문 생성 API**

- **API 명세:**
    - `POST /orders`
    - API 문서 링크: [API Docs 링크 - 주문 생성] (<- 실제 링크 대신 예시)
- **권한 :**
    - 로그인한 사용자 (`IsAuthenticatedUser`)
- **구현 상세 :**
    - **요청 (Request Body):** 장바구니 항목 ID 목록, 배송지 정보, 사용할 쿠폰/포인트, 선택한 결제 수단 등.
    - **처리 로직:**
        1. 요청 데이터 유효성 검증 (배송지, 상품 재고, 쿠폰/포인트 유효성 등).
        2. 주문 총액 계산 (상품 가격, 할인, 배송비 등 포함).
        3. `orders`, `order_items` 테이블에 주문 정보 저장 (초기 상태: '결제 대기 중').
        4. 결제 정보(`payments` 테이블) 생성.
        5. 선택된 결제 수단에 따라 외부 결제 연동 모듈 호출 (e.g., PG사 API 호출).
        6. 결제 요청에 필요한 정보 (결제 창 URL, 필요 파라미터 등)를 응답으로 반환.
    - **트랜잭션 관리:** 재고 차감, 주문/결제 정보 생성은 원자적(atomic)으로 처리되어야 함 (실패 시 롤백).
    - **재고 처리:** 주문 생성 시점에 상품 재고를 확인하고, '가용 재고'를 확보(차감 또는 예약)하는 로직 필요 (동시성 제어 고려).

### **주문 목록 조회 API**

- **API 명세:**
    - `GET /orders`
    - 쿼리 파라미터: `page`, `page_size`, `status` (주문 상태 필터), `start_date`, `end_date` (기간 필터)
    - API 문서 링크: [API Docs 링크 - 주문 목록 조회]
- **권한:**
    - 로그인한 사용자 (`IsAuthenticatedUser`): 자신의 주문 목록만 조회 가능
    - 관리자 권한 (`IsAdminUser`): 모든 사용자 또는 특정 사용자 주문 목록 조회 가능 (별도 파라미터 필요 시 명시)
- **구현 상세:**
    - 사용자 ID를 기준으로 `orders` 테이블 조회.
    - 페이지네이션(Pagination) 구현.
    - 주문 상태, 주문 일시 등 기본 정보와 대표 상품 이미지/이름 등을 포함하여 응답.
    - 성능을 위해 적절한 인덱스(Index) 필요 (e.g., `user_id`, `created_at`, `status`).

### **주문 상세 조회 API**

- **API 명세:**
    - `GET /orders/{order_id}`
    - API 문서 링크: [API Docs 링크 - 주문 상세 조회]
- **권한:**
    - 로그인한 사용자 (`IsAuthenticatedUser`): 자신의 주문만 조회 가능
    - 관리자 권한 (`IsAdminUser`): 모든 주문 조회 가능
- **구현 상세:**
    - `order_id`를 기준으로 `orders`, `order_items`, `payments`, `shipments` 테이블 정보를 조합하여 응답.
    - 주문자 정보, 배송지 정보, 주문 상품 상세 내역, 결제 정보, 배송 상태 등을 포함.
    - 권한 검증: 요청한 사용자가 해당 `order_id`의 소유자인지 확인.

### **주문 취소 API**

- **API 명세:**
    - `POST /orders/{order_id}/cancel`
    - API 문서 링크: [API Docs 링크 - 주문 취소]
- **권한:**
    - 로그인한 사용자 (`IsAuthenticatedUser`): 자신의 주문만 취소 가능 (특정 상태에서만)
    - 관리자 권한 (`IsAdminUser`): 모든 주문 취소 가능
- **구현 상세:**
    - `order_id`로 주문 정보 조회.
    - **취소 가능 상태 검증:** 주문 상태가 '결제 완료', '상품 준비 중' 등 취소 가능한 상태인지 확인 (e.g., '배송 중' 이후는 취소 불가).
    - **결제 취소 처리:** `payments` 정보를 기반으로 외부 결제 연동 모듈을 통해 결제 취소 요청.
    - 결제 취소 성공 시, 주문 상태를 '취소 완료'로 변경 (`orders` 테이블 업데이트).
    - 사용한 쿠폰/포인트 복원 처리.
    - 차감했던 상품 재고 복원 처리.
    - 트랜잭션 관리: 결제 취소, 상태 변경, 재고/쿠폰 복원이 모두 성공해야 함.

### **결제 가능 수단 조회 API**

- **API 명세:**
    - `GET /payments/options`
    - API 문서 링크: [API Docs 링크 - 결제 수단 조회]
- **권한:**
    - 모든 사용자 (로그인/비로그인 상태 무관하게 조회 가능할 수 있음, 정책에 따라 결정)
- **구현 상세:**
    - 현재 시스템에서 활성화된 결제 수단 목록 (신용카드, OO페이, 계좌이체 등)을 응답.
    - 필요시 사용자 또는 주문 금액에 따라 노출되는 결제 수단이 달라질 수 있음.

### **결제 결과 웹훅(Webhook) 처리 API**

- **API 명세:**
    - `POST /payments/webhook/callback` (경로는 PG사/결제 수단별로 다를 수 있음)
    - (API 문서는 내부용 또는 PG사 가이드 참조)
- **권한:**
    - 특정 IP 대역 또는 인증키 기반 접근 제어 (PG사 서버만 호출 가능하도록)
- **구현 상세:**
    - PG(Payment Gateway)사에서 결제 완료/실패 등 결과 정보를 비동기적으로 전송받는 엔드포인트.
    - 수신된 데이터의 유효성 및 위변조 검증 (PG사에서 제공하는 방식 사용).
    - 웹훅 데이터 내 주문번호(또는 거래번호)를 이용해 `payments` 및 `orders` 테이블 정보 업데이트 (결제 상태, 주문 상태 변경 등).
    - 결제 성공 시, 사용자에게 알림 발송, 배송 준비 시작 등의 후속 프로세스 트리거.
    - 멱등성(Idempotency) 고려: 동일한 웹훅이 여러 번 호출되더라도 결과가 동일하게 처리되도록 구현.

    - 개인정보 처리 방침 및 법적 요구사항을 고려하여 주문 및 결제 관련 데이터의 보관 기간 및 파기 정책에 대한 명확한 기준 설정 필요. ([관련자: 법무팀/개인정보 담당자 @이름])

- **주문 상태 (Order Status):**
    
    - `PENDING_PAYMENT`: 결제 대기 중
    - `PAID`: 결제 완료
    - `PREPARING_PRODUCT`: 상품 준비 중
    - `SHIPPING`: 배송 중
    - `DELIVERED`: 배송 완료
    - `CANCELLED`: 주문 취소
    - `PAYMENT_FAILED`: 결제 실패
- **PG (Payment Gateway):** 신용카드, 간편결제 등 다양한 결제 수단을 안전하고 편리하게 이용할 수 있도록 지원하는 결제 대행 서비스.
    
- **웹훅 (Webhook):** 특정 이벤트(예: 결제 완료)가 발생했을 때, 한 시스템(PG사)에서 다른 시스템(우리 서비스)으로 실시간 알림 데이터를 보내는 메커니즘.
