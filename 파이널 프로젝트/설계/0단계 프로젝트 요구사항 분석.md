도메인을 나눈 근거 : 각 영역이 가진 업무 책임, 데이터, 비즈니스 규칙이 서로 분리가 되는지.

여기서는 관리하는 핵심 대상이 서로 다르고 각자의 비즈니스 규칙을 세웠을 때 충돌하지 않을 정도로.

회원 도메인
	정의 : 사용자가 서비스에 가입하고 탈퇴 한다.

	### 비즈니스 규칙 : 
	1. 카카오 인증과 서비스 필수 약관에 동의해야 회원 가입이 완료된다.
	2. 회원가입 한 사용자는 로그인 할 수 있어야 한다. 
	3. 카카오 고유 회원 ID 1개당 회원은 1명이다.
	4. 가입한 사용자는 탈퇴 할 수 있어야 한다.
	5. 탈퇴 한 사용자의 데이터는 7일 간 보관한다.
	6. 7일 이후 탈퇴 한 사용자는 재가입이 불가하다.
	7. 탈퇴한 사용자에게 교환 요청을 보낼 수 없다.

	### 기능적 요구사항 :
	1. 사용자가 카카오 로그인을 작성하면 카카오 인증 화면으로 이동한다.
	2. 카카오 인증에 성공하면 카카오 고유 회원 ID로 기존 회원 여부를 확인한다.
	3. 기존 회원이면 로그인, 기존 회원이 아니면 회원가입으로 한다.
	4. 인증에 실패하게 되면 로그인 처리가 아닌, 실패 처리를 한다.
	5. 동일한 카카오 회원 ID로 중복 회원을 생성하지 않는다.
	6. 로그인한 회원은 로그 아웃이 가능하다.
	7. 로그아웃 하면 현재 로그인 세션을 종료한다.
	8. 회원의 상태는 정상, 탈퇴, 제한 으로 구분한다.
	9. 탈퇴는 마이페이지에서 가능하다.
	10. 탈퇴 후 7일간은 데이터를 남겨두고 7일(168시간)이 지나면 데이터를 삭제 한다.

	### 비기능적 요구사항 :
	1. 카카오 로그인 완료 후 3초 이내에 서비스 로그인 상태를 표시한다.
	2. 로그인 상태 확인 요청은 불필요하게 반복하지 않는다.
	3. 카카오 인증 정보와 서비스 토큰은 HTTPS 로만 전송한다.
	4. Access Token과 Refersh Token은 URL에 노출하지 않는다.
	5. 인증되지 않은 사용자는 접근을 제한해야한다.
	6. 탈퇴 하거나 폐기된 토큰은 다시 사용 할 수 없어야 한다.
	7. 회원의 민감한 정보는 암호화 하여 저장한다.
	8. 회원가입, 탈퇴, 계정 제한, 상태 변경 시각을 기록한다.
	
그룹 도메인
	정의 : 그룹의 생성과 관리, 그룹 내 물품 공개를 관리 하는 영역.

	### 비즈니스 규칙 : 
	1. 1명 당 최대 그룹 가입은 5개이다.
	2. 가입 한 그룹은 탈퇴 할 수 있다.
	3. 그룹 탈퇴는 계정 탈퇴와 다르게 모든 데이터를 보관하지 않는다.
	4. 그룹 이름은 중복이 가능하다.
	5. 그룹을 생성/가입은 위치 인증이 되어야 가능하다.
	6. 그룹은 0명이 되면 자동으로 삭제 된다.

	### 기능적 요구사항 :
	1. 사용자는 그룹 목록을 검색 할 수 있다.
	2. 이름이 같은 그룹이 있을 수 있으므로 그룹의 위치를 추가도 제공한다.
	3. 그룹에 가입된 사용자만 그룹 내의 물품을 조회 할 수 있다.
	4. 로그인한 사용자는 그룹 생성 정보를 입력해서 그룹을 생성 할 수 있다.
	5. 그룹 생성시에 사용자의 위치와 생성된 그룹의 도로명의 위치를 비교한다.
	6. 위치 비교가 허용 범위(500m) 밖이면 제한하고 안내 문구를 띄운다.
	7. 그룹의 생성자는 그룹의 회원으로 가입된다.
	8. 그룹에서 탈퇴하면 그룹에 대한 접근 권한을 제거 한다.
	9. 최대 제한 그룹에 가입하려고 하면 제한 문구와 함께 가입을 제한한다. 
	10. 그룹이 0명이 되면 해당 그룹을 자동으로 삭제 처리 한다.

	### 비기능적 요구사항 : 
	1. 그룹 목록과 검색 결과는 2초 이내에 표시한다.
	2. 그룹 상세 정보는 1초 이내에 조회 한다.
	3. 위치 인증 결과는 3초 이내에 제공한다.
	4. 동일한 회원이 같은 그룹에 중복 가입되지 않아야 한다.
	5. 마지막 회원이 탈퇴한 그룹은 중복 삭제나 오류 없이 한 번만 삭제 되어야 한다.
	6. 그룹 가입을 5개 넘게 동시에 가입해도 5개를 초과하지 않아야 한다.

 물품/게시글 도메인
	정의 : 물품 등록과 게시글 작성을 관리하는 영역.

	### 비즈니스 규칙 :
	1.  로그인 한 회원만 물품을 등록 할 수 있다.
	2. 게시글 작성 시 필수 항목을 모두 입력해야 한다.
	3. 물품을 등록한 회원만 해당 물품을 수정하거나 삭제 할 수 있다.
	4. 필수 등록 항목의 정책을 모두 만족해야 등록이 가능하다.
	5. 게시글 작성, 수정 시점을 기록한다.

	### 기능적 요구사항
	1. 그룹에 가입하지 않은 상태면, 물건 조회를 제한한다.
	2. 물품이 없는 상태면 물품이 없는 상태를 명시한다.
	3. 사용자는 물품 목록에서 물품 상세 화면으로 이동할 수 있게 한다.
	4. 삭제 되거나 비공개 처리된 물품은 상세 화면으로 넘어가기를 제한 한다.
	5. 로그인 한 회원은 물품 등록 화면을 통해 게시글을 작성 할 수 있게 한다.
	6. 물품 등록에서 필수값이 없거나 형식을 준수 하지 않으면 저장 시키지 않고 문구를 안내 한다.
	7. 등록한 사용자는 상품을 수정 할 수 있다.
	8. 등록한 사용자는 상품을 삭제 할 수 있다. 
	9. 물품 등록 중에 뒤로가기를 누르면 임시저장이 되지 않는다.
	10. 게시글은 선택된 그룹에만 등록된다.
	11. 게시글 작성 표기와 시간은 KST와 공통 시간 표기 정책에 따라서 표기한다.

	### 비기능적 요구사항
	1. 물품 목록은 일반적인 네트워크 환경에서 2초 이내에 표시한다.
	2. 목록에서는 원본 이미지가 아닌 리사이징 된 이미지를 사용한다.
	3. 화면에 보이지 않는 이미지는 필요할 때 불러 온다.
	4. 물품 상세 이미지도 단계적으로 로딩 한다.
	5. 이미지 처리 실패시 게시글을 불완전한 상태로 저장하지 않는다.
	6. 네트워크 오류나 이미지 업로드가 실패해도 기존 게시글 정보가 손상되지 않아야 한다.
	7. 게시글 작성, 수정 시각은 서버 시각을 기준으로 일관되게 관리한다.


요청 도메인
	정의 : 요청자가 자신의 물품과 상대방의 물품을 선택하여 교환 요청을 생성 및 수정을 관리하는 영역.

	### 비즈니스 규칙 : 
	1. 로그인한 회원만 교환 요청을 보낼 수 있다.
	2. 자신의 요청에는 교환을 보낼 수 없다ㅏ.
	3. 요청자는 본인이 보유한 물품만 교환 물품으로 선택 할 수 있다.
	4. 요청 대상 물품과 요청자 물품은 1개 이상 이어야 하고, 등록된 최대 수량을 초과 할 수 없다.
	5. 탈퇴한 회원과 제한된 회원에게는 교환 요청을 보낼 수 없다.
	6. 요청은 대상 물품이 거래 완료 상태가 되면 자동으로 취소가 된다.
	7. 동일한 물품에 대해서는 중복 요청이 가도 하나의 요청만 처리한다.
	8. 요청을 전송하면 상대방의 채팅에 요청 내용이 표시된다. 
	9. 요청자는 상대방이 응답하기 전까지 본인이 보낸 요청 내용을 수정 할 수 있다.
	10. 상대방은 전달 받은 요청 내용을 조회만 할 수 있으며 수정 할 수 없다. 

	### 기능적 요구사항 :
	1. 로그인한 사용자는 교환 요청을 작성 할 수 있다.
	2. 본인이 보낸 요청에 대해서만 수정 및 취소 할 수 있다.
	3. 요청의 수량은 0이하로 갈 수 없고 보유 수량 이하의 정수로만 등록이 가능하다.
	4. 탈퇴한 회원이나 제한된 회원의 물품에는 요청을 보낼 수 없다.
	5. 요청 필수 사항을 만족하지 않으면 요청을 제한 하고 안내 문구를 보여준다.
	6. 요청의 수량 조절은 버튼과 직접 입력으로 할 수 있다.
	7. 가치 비교를 해 실시간으로 안내 문구를 보여준다.

	### 비기능적 요구사항 : 
	1. 교환 요청 화면은 2초 이내에 표시한다.
	2. 물품의 수량을 변경하면 즉시 유효성 결과를 표시한다.
	3. 요청자만 물품과 수량을 선택 할 수 있어야 한다.
	4. 요청 수량은 전송 시점에 다시 검증되어야 한다.
	5. 여러 요청이 동시에 들어와도 하나의 요청만 처리해야한다.
	6. 여러 요청이 동시에 전송되어도 보유 수량을 초과하는 요청은 생성되지 말아야 한다.
	7. 요청이 변경된 경우 변경된 시간을 기록한다.
	8. 요청 내용과 물품 정보는 필요한 사용자에게만 제공한다.
	

교환 진행 도메인
	정의 : 교환 요청에 대한 수락, 거절, 완료와 물품의 거래 상태를 관리하는 영역.

	### 비즈니스 규칙 :
	1. 상대방은 교환 요청을 수락하거나 거절 할 수 있다.
	2. 거래 완료의 물품에 대해서는 새로운 요청을 받을 수 없다.
	3. 동일한 요청을 여러 번 수락하거나 완료 처리 할 수 없다.
	4. 교환이 거절되거나 완료 후 요청 상태를 변경 할 수 없다.

	### 기능적 요구사항 :
	1. 상대방은 받은 교환 요청을 조회 할 수 있다.
	2. 요청을 받은 상대방은 교환을 완료하거나 거절 할 수 있다.
	3. 교환이 완료되면 재고가 차감되고 남은 재고가 0이면 거래 완료 상태로 만든다.
	4. 상태 변경 결과는 판매자 구매자의 채팅화면과 물품 화면에 반영한다.
	5. 한번 교환 완료, 거절 된 요청에 대해서는 되돌릴 수 없다.

	### 비기능적 요구사항 :
	1. 수락, 거절, 완료 처리 결과를 2초 이내에 표시한다.
	2. 이후 3초 내에 채팅과 물품 상세에 반영한다.
	3. 상태 조회시 최신 상태를 제공한다.
	4. 완료, 거절은 요청을 받은 사용자만 상태를 변경 할 수 있다.
	5. 권한이 없는 사용자가 API나 직접 접근으로 상태를 변경 할 수 없어야 한다.
	6. 같은 버튼을 여러 번 눌러도 수락, 거절 완료 처리가 중복으로 실행되지 않아야 한다.
	7. 물품에 대한 상태 변화가 모든 화면에 일관되게 표시해야한다.

채팅 도메인
	정의 : 교환 상대방 간의 1:1 대화와 메시지, 시스템 메시지, 교환 요청 요약 정보를 관리하는 영역.

	### 비즈니스 규칙 :
	1. 채팅방은 두명의 회원만 참여하는 1:1 대화 구조로 진행한다.
	2. 채팅방은 요청 제안을 보내는 순간 자동으로 열린다.
	3. 채팅방의 기준은 사람이 아닌 물품을 기준으로 한다.
	4. 참여자 중 1명이 나가 채팅방 참여 인원이 총 1명이 되면 채팅이 닫힌다.
	5. 메시지 수정과 삭제를 허용하지 않는다.
	6. 채팅방의 참여자만 메시지를 보내고 조회 할 수 있다.
	7. 공백의 채팅은 전송이 불가능하게 한다.
	8. 메시지는 시간과 작성자 내용을 포함한다.
	9. 시간은 서버 시간을 기준으로 표시한다. (kst)
	10. 시스템 메시지는 사용자가 수정하거나 삭제 할 수 없다. 
	11. 시스템 메시지는 사용자 메시지와 구분된다.
	12. 계정이 제한 되어도 기존 채팅과 진행 중인 채팅을 자동 종료하지 않는다.
	13. 제한되거나 탈퇴한 사용자에게는 프로필에 명시하여 채팅에서도 확인 할 수 있게 한다. 

	### 기능적 요구사항 :
	1. 채팅방 참여자만 해당 채팅방에 접근 할 수 있다.
	2. 참여자는 메시지를 조회할 수 있고 전송 할 수 있다.
	3. 전송된 메시지는 작성자와 내용, 전송 시간을 포함한다.
	4. 계정이 제한 되어도 기존 채팅방과 진행 중인 교환을 자동 종료하지 않는다.
	5. 제한되거나 탈퇴된 회원에 대해서는 "제한된 사용자입니다."를 표시한다.
	6. 채팅 메시지의 시간은 KST와 공통 시간 표기 정책에 따른다.

	### 비기능적 요구사항 : 
	1. 각 사용자의 채팅 참여는 2초 이내에 한다.
	2. 메시지 전송 결과는 1초 이내에 반영되게 한다.
	3. 교환 요청이나 거절에 대한 시스템 메시지는 3초 이내에 채팅 창 화면에 반영되도록 한다.
	4. 채팅방 참여자만 채팅에 참가 할 수 있도록한다.
	5. session ID를 알아도 채팅방의 내용은 볼 수 없게 한다.
	6. 시스템 메시지와 현재 교환 상태는 일관되어야 한다.
	7. 네트워크가 끊겨도 기존 채팅 이력은 손상되지 않아야 한다.
	8. 동시에 여러 채팅방이 이용 되더라도 메시지 전송 지연이 과도하게 증가하지 않아야 한다.
	9. 채팅 연결이 끊어지면 자동으로 재연결을 지원해야 한다.

위치 인증 도메인
	정의 : 그룹 생성과 가입 시 필요한 위치 인증을 관리하는 영역.

	### 비즈니스 규칙 :
	1. 사용자는 위치 인증을 동의 해야만 이용 할 수 있다.
	2. 그룹 생성 시, 생성자의 현재 위치와 입력한 그룹 위치를 비교한다.
	3. 그룹 생성 시, 비교된 그룹 위치가 500M 이내여야만 그룹을 생성 할 수 있다.
	4. 그룹 가입 시, 생성된 그룹의 위치와 가입자의 위치를 비교한다.
	5. 그룹 가입 시, 비교된 위치가 500m 이내여야만 그룹을 가입 할 수 있다.
	6. 중복 요청 시 마지막으로 요청된 위치를 기준으로 한다.
	7. 위치 인증에 성공하지 않은 사용자는 위치 인증이 필요한 작업을 완료 할 수 없다.
	8. 그룹의 기준 위치는 변경되지 않는다.
	9. 위치 인증을 위해 수집한 정보는 다른 회원에게 공개하지 않는다. 

	### 기능적 요구사항
	1. 위치 인증이 필요한 기능을 실행하면 위치 권한을 요청한다.
	2. 위치 권한이 허용되면 사용자의 현재 위치를 조회 한다.
	3. 현재 위치와 기존 그룹의 위치를 비교해 허용범위(500m) 밖이면 가입 제한과 안내문구를 표시한다.
	4. 위치 인증에 실패하면 다음 절차로 넘어가지 못하게 한다.
	5. 사용자의 위치 정보는 다른 회원에게 표시하지 않고 인증 결과에 대해서만 제공한다.
	
	### 비기능적 요구사항
	1. 위치 인증의 결과를 예시로 5초 이내에 제공해야 한다.
	2. 인증 중 상태는 사용자에게 표시하도록 한다.
	3. 위치 정보를 불필요하게 반복 조회 하지 않는다.
	4. 위치 권한이 없는 사용자에게 인증 결과를 임의로 생성하지 않게 한다.
	5. 위치 조작이나 비정상적인 인증 시도를 탐지 할 수 있어야 한다.
	6. 권한 거부, GPS 오류, 인증 실패의 원인을 명확하게 표시한다.
	7. 인증 대상 그룹, 인증 결과, 인증 시각을 기록한다.
