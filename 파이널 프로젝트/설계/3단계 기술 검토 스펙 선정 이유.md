

# JAVA
java를 선정한 이유

###### 선정 기준
1. 타입 안정성과 오류 조기 발견 
	- Python 같은 경우는 동적 언어이고, Java는 정적 언어이기 때문에,
	- python은 직접 실행해봐야 오류를 알 수 있다. (런타임 오류)
	- java는 직접 실행해보기 전에 오류를 알 수 있다. (컴파일 오류)
	런타임 오류 vs 컴파일 오류?
		컴파일 오류는 실행 전에 컴파일러가 오류를 감지하고 실행 자체를 막는다. 
		런타임 오류는 프로그램 실행은 되지만 특정 상황에 JVM이나 OS에서 오류가 터지기 때문에 위험도가 크다.

	따라서 JAVA는 컴파일러가 모든 코드 경로를 정적으로 분석해서, 실행 여부와 무관하게 오류를 찾고 타입이 안맞는 코드의 빌드는 실패 시킨다.
	
2. 실행 최적화 처리 능력
	- 전통적인 Python 은 jit 자체가 활용적이지 않음.
		- Python의 jit은 동적인 타입과 객체 구조를 실행 중 추측해야하기 때문에 jit이 과감하게 최적화하기 어려움.
	- Java의 [[Jit compiler]]는..
		- JAVA의 jit은 정적 타입과 JVM의 강한 런타임 profiling 을 이용해 hot code를 공격적으로 최적화함.

3.  메모리 및 자원 관리의 안정성
	* C언어 같은 경우는 메모리와 자원 관리를 수동적으로 해줘야함.
		* 다 썼으면 malloc이나, free등으로 자원 할당 해제.
	* JAVA는 [[Garbarge Collection]] 로, 자동적으로 자원 할당을 해제한다. 그리고 다양한 알고리즘이 있어서 GC로 인한 애플리케이션 정지 시간을 극도로 줄일 수 있다.
		* C#과 비슷하게, 세대별 GC, Java와 유사..
		* Python은 참조 카운팅을 통해서 자원을 정리하기 때문에, 모든 객체 참조가 일어날 때마다 카운트를 증감 시키는 오버헤드가 있다. 

4.  장기 운영과 장애 분석 편의성
	* JAVA는 운영 중인 서비스에서 문제가 생겼을 때 원인을 진단하는 표준화된 방법이 매우 잘 갖춰져 있다.
		* Thread Dump - 스레드가 멈췄을 때, 실행 중인 모든 스레드의 현재 상태를 그대로 캡쳐 가능.
		* Heap Dump - 메모리 누수 의심될 때, 힙 메모리의 스냅샷을 통째로 가져와 어떤 객체가 참조를 받아 GC 처리가 안되는지 알 수 있음. 
		* GC Viewer - GC 로그를 참고해서 메모리 회수가 얼마나 자주/ 오래 일어나는지 정량적으로 추적 할 수 있다.
	* Python은 런타임 이후에야 타입이 결정되므로, 추적 할 때 훨씬 제한적인 정보만 얻을 수 있다.

## 4. Java 선정 근거

### 4.1 정적 타입 기반의 안정성

Java는 정적·강타입 언어로 변수와 표현식의 타입을 컴파일 시점에 확인한다. 이를 통해 API 계약이나 도메인 모델 변경으로 발생할 수 있는 오류를 실행 전에 발견하기 쉽다.

Python도 타입 힌트를 사용할 수 있지만, Python 런타임은 타입 주석을 기본적으로 강제하지 않으므로 별도의 타입 검사 도구가 필요하다.

### 4.2 백엔드에 적합한 실행 모델

Java 애플리케이션은 JVM 위에서 실행되며, JVM은 하드웨어와 운영체제에 독립적인 class 파일 형식을 사용한다. 따라서 개발·테스트·운영 환경 간 실행 환경을 일관되게 구성하기 쉽다.

JVM은 JIT 컴파일과 여러 GC 구현을 제공하여 장시간 실행되는 서버 애플리케이션의 성능과 메모리 관리를 조정할 수 있다.

### 4.3 동시 요청 처리

Java는 기존 스레드 및 Executor 모델을 제공하며, Java 21부터 Virtual Thread를 사용할 수 있다. Virtual Thread는 I/O 대기가 많은 서버 애플리케이션에서 높은 동시성을 확보하는 데 유리하다.

단, Virtual Thread가 CPU 중심 작업 자체를 빠르게 만드는 것은 아니며 실제 효과는 애플리케이션의 workload에 따라 검증해야 한다.

### 4.4 장기 운영과 장애 분석

JDK는 JMX, `java.lang.management`, JConsole, Java Flight Recorder, `jcmd` 등 JVM과 애플리케이션의 메모리·스레드·GC·성능 상태를 분석할 수 있는 도구를 제공한다.

이는 단순히 애플리케이션을 개발하는 것뿐 아니라, 운영 중 발생하는 성능 저하와 장애의 원인을 추적하는 데 도움이 된다.

### 4.5 C#과의 관계

C#과 .NET도 정적 타입, 자동 메모리 관리, 비동기 처리, 크로스플랫폼 실행을 제공하므로 Java가 모든 면에서 우월하다고 볼 수는 없다.

따라서 Java 선정의 근거는 “C#보다 기술적으로 빠르다”가 아니라, 다음과 같은 프로젝트·조직 조건에 두는 것이 적절하다.

- JVM 및 Java 생태계를 활용할 수 있음

- Java 개발 경험이나 기존 코드 자산이 있음

- 운영 환경을 특정 공급업체에 종속시키지 않으려 함

- 장기 운영되는 업무 시스템과 API 서버를 개발함

Microsoft, Azure, Windows, Active Directory 중심 환경이라면 C#이 더 적합할 수 있다.

## 5. 최종 결론

본 시스템은 장기간 운영되는 웹 기반 백엔드로서 초기 개발 속도보다 타입 안정성, 동시 요청 처리, 메모리 관리, 실행 환경의 이식성, 장애 분석 및 유지보수성을 중요하게 고려한다.

Python은 빠른 개발과 데이터·AI 활용에 강점이 있고, C는 하드웨어 제어와 극저수준 최적화에 강점이 있다. C#은 Java와 유사한 수준의 기술적 장점을 제공한다.

그러나 본 프로젝트의 요구사항과 JVM 생태계 활용 가능성을 종합하면, 안정성·성능·운영성·유지보수성의 균형이 좋은 Java를 백엔드 개발 언어로 선정하는 것이 합리적이다.
